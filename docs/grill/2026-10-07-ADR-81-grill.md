## 所見

### 1. 審査の判定の替えの費え

- **M1 直す（V/D）ADR-77 の停止線（P-10.4・R-46 の推奨 70 %・窓は直近に初めて起きた便 20 本）との当たりが書かれていない。** 質の欄の時代に最初の便を持つ bead は 87 本。今は 1 本目の着地が 49 本（56.3 %）で、決定 (5) を当てると 27 本（31.0 %）。20 本の窓では、今は最小 35 %・最大 75 % で、窓の 88.2 % が 70 % を下回る。当てた後は最小 10 %・最大 55 % で、窓の 100 % が下回る（V・w/count427.out の first_run_* と window20_*）。停止線のあいだは構造の直しの行と壊れの札の便だけが流れるが、これらも契約の審査を通るので、質の FAIL は同じ率で当たる。線を解く道が無くなる（D）。直し: 決定 (5) を入れる時機を「停止線が解けた後」にするか、線と質の FAIL の当たりを数で書いて持ち主に問う。数え方の限り: 「初回」は各 bead の pipe の最初の run dir で、R-46 の器の関数（event log から出す・77-7）と同じ数えかは U。
- **M2 直す（V）撤退 (1) の閾値 30 % に出所が無く、過去の数では最初の窓で当たる。** 質の FAIL の割合の見込みは 58/142＝40.8 %。日ごとでは 10-06 が 49/116（42.2 %）、10-07 が 9/26（34.6 %）で、どちらも 30 % を越える（V・by_day）。稿は「欄の後の数は U」と書きながら、閾値を唯一の既知の数より下に置いている。直し: 閾値の出所（見込みの下げ幅）を書くか、影の窓（下の S2 の (i)）で測った値から閾値を決める。
- **M3 直す（V/D）型 quality を器の閉じた型に足すと、ADR-77 の P-10.3・P-10.6・P-10.7 が効く。その設計が無い。**

  - 構造の札（P-10.3）: 「型 quality を狙う構造の直しの行」が何かを稿は決めていない。
  - ADR-77 は、審査役の揺れのある型（other・unparsed）を P-10.3 の断りから外した（ADR-77.yaml:28）。審査役が数える quality をどちらに置くかも、稿に無い。

### 2. memo の審査の欄

- **S3 問う（V/D）memo の欄の 3 点。**
  - 鍵 proof は「path か名か、撃った命令と出力の要約の 1 行」の自由な字で、機械が見られるのは空でない事だけ。
  - memo の判定は memo ごとに 1 つの file（state の pipe/memo/<id>/verdict・r424 の notes の「履歴は残らず、上書き」）。撃ち直された memo の unparsed は消えるので、撤退 (4)（7 日の unparsed の件数）は今の置き場からは数えられない（U・event に残るかは照らしていない）。
  - promote を std・line・min に限ると、消すだけ・直すだけの memo（足す物が無い）に「足す物の在りか」の証しを書かせる事になる。keep 62/72 は引き金の読みで止めた物で、この記録と直には関わらない、という稿の読み（F4）はよい（V・r424 の §3）。

### 3. 契約の欄 ladder が形骸にならないか

- **M7 直す（V）preflight の照らしで、中身を崩せる物が無い。**
  - need の証しは「欄 req の id」で足りる。req は必ず在る欄（scribe2/crates/scribe2/src/pipe/table.rs:120）なので、どの契約も自分の req を写せば通る。
  - exists の証しには「none=<語>」がいつでも使える。std と line の段は空でない事だけを見る。
  - 中身に当たる照らしは「exists の path が木に在る」と「最後の要素の path が write-set に在る」の 2 つだけで、どちらも探した事の証しにならない。丙を退けた訳（中身が空でも通る）が、甲の preflight にもそのまま当たる。
  - 直し（器に既に在る物で足りる）: (a) 「none=<語>」の語を base で git grep するか、索引（code-facts の照らしが読む base の索引・pipe/cli/intake/code_facts.rs:1-7）で引き、識別子として在れば断る。(b) 最後の要素の新しい名が base に無い事を照らす（約束の行の symbols の「+」が既にこの照らしを持つ・pipe/refuse.rs:424 の PromiseSymbolUnresolved「+ は base に無い新設の名」）。
- **S4 問う（V）新しい物の列は、既に在る宣言と重なる（条 P-27.1 の段 2）。**
  - write-set の項目の「+」（新しい file・NEW_FILE・pipe/cli/intake/refusal.rs:126）と、約束の行の symbols の「+」が既に「新しく足す物」を名乗る。欄 ladder の最後の要素の「<path>#<名>」の列は 3 本目の文法になる。今の「+」の文法を広げる形との比べを書く。
  - 足す定義が無い契約の逃げ道も要る。着地した 85 便のうち、.rs の新しい定義（fn・struct・enum・const・static・type・trait・mod・歯を含む）を 1 つも足さない便は 3 本（V・w/extra427.out）。その形を書く。

### 4. 実装役に何も足さない論

- **M5 直す（V/D）実装の時に入る、名前違いの近い複製を止める所が無い。** 契約が名指さない補助関数（goal に仕える private な物）は、次の 4 つのどれにも掛からない。
  - (a) 契約の審査は実装の前で、diff が無い（pipe/review.rs:1-6）。
  - (b) gate の contract-fit は goal と done の外を数えるだけで、goal に仕える補助関数は外ではない（ADR-63 の決定 (6)）。
  - (c) gate は質を数えない（ADR-63 の決定 (7) の乙'「gate は質を数えない」）。
  - (d) ADR-80 の同じ本文の門は、字句が全く同じで本文 3 行以上の物だけを落とす（w420a/w/ADR-80.yaml:24）。r421 の 3 行の床では 13 組を拾い、正解 7・字は同じで指す先が違う 3・新しい本物 3 だった（r421/w/notes.md:9,61）。
  - 今日の 7 組は字句の hash で拾った同一の組なので、その形は ADR-80 の門で足りる（D）。名を替えた近い複製は、稿の決定 (4) も自分で「止まらない」と書いている。それでも plain は「実装の係には何も足しません（…契約の外の物は既に別の検査が止めます）」と書く。
  - 直し: 失う物と plain にこの漏れを書く。測りの鍵（例: ADR-80 の夜の検出線の、識別子を番号に替えた近い組の 7 日の数）を撤退に足すか、案を足す。案は、gate が diff から読んだ新しい item の名を、契約の欄 ladder の宣言の列と照らす形（自己申告ではなく、ADR-80 の字句の割りを使う）。丁を退けた訳（自己申告で照らす物が増えない）はこの形には当たらない。

## 決定はしご（条 P-27.1）と消す物の名指し（条 P-27.2）— ADR-81 自身の足し

- 段 1 要るか: 一部しか立たない。base に既に在る code だけを指す 33 本を除くと、便が足した物への指摘で落ちるのは多くて 25 本（M4）。要るかの訳を数え直す。
