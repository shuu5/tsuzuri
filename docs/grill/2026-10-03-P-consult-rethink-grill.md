# grill 論点 P — 相談の窓 consult の作り直しの反対側からの検証（判断の記録 ADR-29 に添える）

- 対象: 判断の記録の案 ADR-29（相談の窓 consult の作り直し）の第 1 版と第 2 版（commit したのは第 3 版）。発端は memo t3-hub.75（持ち主の 5 つの答え・器の席の答え・席の調べ）。
- 検証役: qv44a（Claude Code と tmux の事実・小さな実験）と qv44b（設計の食い違い）。どちらも AI・Opus・起草者と別の文脈。commit・台帳の書き・repo の書きはしていない。tsuzuri は main 67be4cd8、器（scribe2）は main 57dc1e5c を読んだ。
- 実験の範囲（qv44a）: 席の scratchpad の下の dir だけで、非対話の Claude Code（claude -p・haiku・念入りさ low・120 秒の上限）を 10 回撃った。器の plugin は渡していない。tmux は独立の socket だけで試した。Claude Code の版は 2.1.288。
- 処分: 席は第 1 版の重い穴の全部を第 2 版で直し（6 節）、第 2 版の照らし直しの穴を第 3 版で直した（7 節）。持ち主に問う論点は 8 節。
- 総合: 第 1 版は、渡し方（窓どうしの連絡）・守り（許可の設定と plugin の hook）・board の button の道・部分の置き換えの名指し、の 4 つが通らなかった。第 2 版と第 3 版は、受け方を席の背景の常の見張りに、守りを制限の形の起動に、記帳を memo と根の bead の型付きの行に替えた。

## 1. 窓どうしの連絡は許可の形の違う席に止め置かれる（qv44a・重い）

案の第 1 版は、所見の口が出した 1 行を、相談の窓が Claude Code の窓どうしの連絡（SendMessage）で席へ送る形だった。

- （verified・実験 R5・R6）受け手を確かめを飛ばす形（bypass）、送り手を許可を聞かない形（dontAsk）で起こして送った。送り手の道具は成功を返したが、受け手の側で止め置かれ（held・cause = mode-mismatch）、最後に捨てられた（discarded）。受け手の model はその文を見ていない。
- （verified・Claude Code の文書の cross-session-messaging）受け手が bypass の組なら、送り手も bypass の組でない限り、文を持ち主の承認まで止め置き、承認の窓は既定 5 分で切れて文を落とす。止め置きを外す設定は、管理の設定か起動の旗か user の設定にしか置けず、project の設定からは外せない。
- 席は bypass で動いている。よって相談の窓からの 1 行は、席の端末に承認を求める窓を出して止まる。
- （verified・code と登録）席の名は「cwd の名と起動ごとの乱数 2 字」で、起こし直しで変わる。

## 2. 守りの穴（qv44a・qv44b・重い）

- （verified・実験 R1）許可を聞かない形でも、口座の設定の許す一覧（殻の命令の bash・git など）はそのまま効き、`bash -c` で file が書けた。--settings の許す一覧は口座の物と合わさり、狭められない。
- （verified・実験 R4）守りの hook が終了 code 1 で落ちた時と時間切れの時、道具はそのまま走った。止まったのは終了 code 2 だけ。
- （verified・文書と init の道具の列）許しの要らない道具（Agent・Skill・CronCreate・RemoteTrigger・PushNotification など）は守りの外で走る。殻の命令の tmux で席の窓に字を打ち込める（inferred）。
- （verified・実験 R8）許す一覧に入れた読む命令も、書く旗（git diff の --output）で file を書けた。
- （inferred）plugin の hook が撃つ tz が無いか古いと、hook は落ちて通す向きに倒れる。

## 3. 制限の形の起動（qv44a・第 2 版の土台）

- （verified・実験 R7〜R10）制限の形（--restricted）で起こすと、口座の設定の許す一覧・hook・環境の値を読まない（`git --version` と `bash -c` が断られ、口座の SessionStart の hook が撃たれず、環境の値が hook から見えなかった）。
- （verified）--settings の hook と、殻の命令の許し（Bash(git log:*) の形）は効く。書きの許しは Edit の規則に絶対 path（// の頭）で書いた時だけ効き、Write の規則は読まれない。
- （verified）file の道具は作業の dir と足した dir（--add-dir）の外を読めない・書けない（許しの規則より強い）。
- （verified）渡した道具（--tools）だけが在り、Agent・Skill・SendMessage・ToolSearch・web の道具は消える。MCP の道具は残るので、別に断る旗が要る。
- （verified）hook が落ちた時も、許しの無い命令は断られた（口座の許す一覧が消えたため）。
- （verified）確かめを飛ばす形と制限の形は一緒に使えない（起動が断る）。口座の認証は効いたまま。
- （inferred・help と文書と code の字）対話の窓でも使える。

## 4. board の button の道（qv44b・重い）

第 1 版は「方針の欄と同じく承認として数えない記録にし、裁定と同じ配達の道で届ける」としていた。

- （verified・tsuzuri の code）方針の口は配達しない。配達の道が拾うのは label が問いの bead の notes の「裁定 id =」の行だけで、停止の hook と道具の周の hook も同じ関数を使う。
- （verified・器の code）器の配達の口が送る字は「裁定 <id> が届いた」に決まっている。
- 帰結: 裁定の道に載せると相談の頼みが持ち主の裁定に見え、方針の形に載せると届かない。
- 器の席の答え（2026-10-03）: 配達の口に種類を足すのは受けられる形だが、器の要件の改訂（持ち主が起こす）と器の判断の記録と契約が要る。intake:memo の label を持つ bead は memo と読まれ、閉じの頭と審査の列が相談の一生に合わない。相談の記帳は tsuzuri の側に置くのを推す。

## 5. 名指しと要件の漏れ（qv44b）

- （重い）部分の置き換えが、ADR-10 決定 (4) に無い字（器の口）を名指していた。ADR-10 決定 (4)(9) の残りの字の扱いが無く、ADR-10 とこの記録の決定の番号が混ざっていた。
- （重い）封の掛かった ADR-27 の帯の項目・窓・吹き出しを、名指さずに変えていた。
- （中）ADR-10 決定 (1) の「持ち主と直に話す」「model は持ち主が選び」が、問う窓と食い違う。
- （中）席が自分で起こす問う窓に上限が無く、ADR-12 で軽くした重さが戻りうる。
- （中）持ち主の手の数え（2 つ）が少なく出ていた。
- （中）群の移動で、話す窓は前の口座に残り、問う窓は席の起こし直しで止まりうる。
- （軽）選ぶ形の問いの窓（D-3）・語彙表と scope の字・basis の漏れ・平易文の言い過ぎ。
- 撤退の条件の (2)(3) は、記録の置き場が無く数えられなかった。

## 8. 持ち主に問う論点（推奨つき）

1. board の button の届け方: 推奨は、席が背景に見張りを常に置く形（器の変更なし）。代わりは、器の配達の口に相談の 1 種類を足す形（器の要件の改訂を持ち主が器の側で起こす）と、見張りなしで席の hook と器の管理の合図だけで拾う形（待ちの席では 40 分以上遅れる）。
2. 口座（仕組みをそろえる）の読み: 推奨は、席と同じ口座で開き、口座が移っても開いている窓は前の口座のまま、上限で止まったら開き直す形。強い model の使用量は器の model 別の見張りには入らない。代わりは、器が相談の窓も席と同じく移す形（器の変更）。
3. 席が自分で問う範囲: 推奨は、同時に 1 本・1 日 3 本・越えたら問う（持ち主の言葉で開いた分は数えない）。代わりは、自由と、持ち主が言った時だけ。
4. 相談の窓の守り: 推奨は、いつもの host の守りの代わりに、より狭い相談の守りだけを掛ける形。代わりは、host の守りも写して重ねる形。
5. 相談の窓に許す事: 推奨は、web の調べは既定で無し（開く時に足せる）、build と試しに動かすことは持たせず席に頼む形。代わりは、web をいつも許す形と、build と試しも許す形（前の版の討論の記録と器の相談席は実験を許していた）。
6. 話す窓の場所と閉じ方: 推奨は、PC の端末の tmux の窓で話し、閉じるのは持ち主（終えると言えば席が閉じる）。
7. ほかの project: 推奨は、ほかの project でも動く形に作り、使い始めは project ごとに持ち主が決める（その project の state dir の host の宣言に 1 行足す）。

## 9. 持ち主の答え（問い t3-hub.75.1）と第 4 版

持ち主はチャットで答えた（2026-10-02T22:38Z・裁定 t3-hub.75.1:20261002T2238Z-1・逐語は問いの notes）。論点 4 と 5 を替え、ほかは推奨のとおりとし、相談の窓を 1 つの議題に限らない自由な調べと検証の場にするよう求めた。

- 論点 4（守り）: 相談の窓は、新しい技術のスクラッチの実験や、データの検証のプログラムを組めるべきで、プロジェクトを汚さない形であること。調査のレポートも作れるべきで、直にプロジェクトに保存せず、席に渡して保存するかを選ばせること。
- 論点 5（許す事）: web の調べはいつもできること。
- 自由な場: 1 つの話が終わっても閉じず、途中で /clear して別の話題を検証して結果を席に渡す使い方も、窓が複数在る使い方もある。

これを受けて、守りを閉じた命令の一覧から基本ソフト（OS）の囲いに替える形を、検証役 qv44a が撃って確かめた（非対話の窓の実験 6 回・独立の tmux の socket）。

- （verified）Claude Code の囲い（sandbox・この host では bubblewrap）を、制限の形と許可を聞かない形の窓で有効にし、囲いの外で撃ち直す道を断ると、作業場の中では python と cargo の build と uv（cache を作業場に置いた時）が聞かれずに走った。作業場の外へは基本ソフトが読むだけの file の仕組みとして書かせなかった。囲いを外す引数を付けても効かなかった。
- （verified）囲いの中からは、unix の socket を作る段で止まり、tmux の server に届かない。外の process は見えない。
- （verified）既定のままの穴が 3 つ在り、どれも設定で塞げた。(a) 同じ user の窓の全部が共有する temp の置き場が書ける → 短い私用の temp の置き場で起こす。(b) 足した dir（--add-dir）が殻の命令から書ける → 同じ path を囲いの書きの断りに置く。(c) 資格の file が読める → 囲いの資格の断りに置く。
- （verified）殻の命令のネットワークは許したドメインだけに出られ、許していない https は断られ、ssh は許しの段で断られた。web の調べの道具（WebSearch・WebFetch）は素の名の許しで使え、殻の命令のネットワークを広げなかった。ドメインの全部を許す形は殻のネットワークも開くので書かない（文書からの推し量り）。
- （verified）囲いが起きない時は、起動で止める設定で rc 1 になり、model は撃たれなかった。
- （verified・近似）rootless の podman は、囲いの中からは起きない（囲いの user の名前空間で uid の写しを作れない・unix の socket を作れない）。container を使うなら、作業場の外に置いた固定の包みの命令だけを囲いの外で撃ち、包みが繋ぐ dir とネットワークを決める形になる（推し量り）。
- （inferred）対話の窓でも同じ設定が効く見込み（文書から）。持ち主が対話の窓で ! で打つ命令は囲いの外で走る。
- 残る外への道は web の調べの道具で、持ち主はいつもの web の調べを求めた。

第 4 版は、決定 (1) に ADR-10 決定 (3)（所見の欄に話題と添え物）と (7)（使い捨てから自由な場へ）と (8)（権能）の置き換えを足し、決定 (3) を自由な場に、決定 (4) の記帳を窓の開きと閉じと話題ごとの所見の行に、決定 (5) に窓ごとの作業場（席の drafts の下）を、決定 (7) を基本ソフトの囲いに、決定 (9) に添え物の保存の選びを足した。package を入れる実験の形（container の包みか、囲いの中で作業場へ入れるか）は持ち主に問う。
