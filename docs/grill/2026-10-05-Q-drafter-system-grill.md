# 反対側からの検証 Q — 起草から着地までの段ごとの持ち手（判断の記録 ADR-63）

- 日: 2026-10-05
- 検証役: qv63（攻め）と qv64（照らし直し）。どちらも AI・起草者と別の独立の文脈・読み取りだけ・cargo なし。
- 攻めた物: 起草係の判断の記録 ADR-63 の雛形と問いの本文と適用の script と起草の記録（第 1 版は係 w229a・第 2 版は係 w231a）。材料は席の調べ（調べの係 4 体の結果と席のまとめ）と、器と tsuzuri の現物（code・契約表・便の判定の記録・毎日の測りの道具）。
- 前置: 持ち主に問う前に、案の穴を反対側から探すために置いた。規則の表の行の改めでも条文の改訂でもない。
- 持ち主の逐語はここに書かない（台帳の問いの notes に在る）。

## 第 1 版への攻め（判じ: 直してから出す・所見 19＝致命 1・要直し 13・軽い 5）

- 致命 1 つ: 群の行の上限を全部の行の検査（共通の verify）に入る歯にすると、上限まで詰めた群の歯を書く行が全部、最後の審査の前の検査で落ちる（並べる便を壊す）。案は越えた群を 2 と書いたが、入口の file を数えるかで 5 にもなり、数え方が決まっていなかった。→ 上限は全部の行を落とす歯にせず、物差しと畳みの行で持つ形に直し、数え方を畳みの道具と同じ（群の dir の直下の .rs・入口の main.rs を除く）と決めた。
- 要直し 13 の主な物:
  - 欄 done-teeth の要否を断るのは器の表の検査（--base を渡した周）だけで、tsuzuri では席の設計の commit の門だけが撃つ。受付と preflight は欄の形だけを見る（code で確かめた）。名乗りの得は 4 件でなく 2 件（約 23 万）。
  - gate の判定と数の食い違いを「まだ分からない」に読むと、前の指摘を次の審査に渡す口が FAIL だけなので回りが閉じない。→ FAIL に読む。
  - 数の誤り（食い違いの便 8→7・5%・ノートの残り・置き済みの行）。
  - 撤退の条件の半分が毎日の物差しの実の項目で測れない。→ 条ごとに項の key で名指し、測れない項は口を作るまで窓を始めない。
  - 器を書く便は同時に 1 本の決まりが器にも席の道具にも無く、2 度破れた。→ 器の床の決定を足した。
  - 次の段の行・週のまとめが席の記憶だけにあり、文脈の圧縮で失われうる。→ 台帳の bead にする。
  - 要件の追跡の広さ（相談の窓の要件がグラフの目指す所を引く）・質の指摘を返す道の無さ・契約審査が質を数える形を測らずに退けた事・予算の下限の得の過大。
- 軽い 5: 天井に残した項目のうち機械で数えられる物・床の記録の撃ち直し・既存の記録との重なり・問いの文の平易さ・問いの数。

## 第 2 版の照らし直し（判じ: 直してから出す・致命 0・要直し 5・軽い 8）

- 第 1 版の所見 19: 塞いだ 17・半分 2（撤退の測り・契約審査が質を数える形の測り方）。
- 新しい要直し 5:
  - 撤退 (1) の基が字の型で数えると 4 件で、名乗りの後も止まらない型を数える。→ 型ごとの項を足し、基と線を直した。
  - 畳みの行の比べる撃ちが全部の群を見ると、ほかの行の着地で畳みの行が落ちる。→ 歯にせず xtask の下の命令にし、畳みの行が書く群と作る群だけを落とす。
  - 契約審査が質を数える形の測りに対照が無い。→ 同じ便 3 本を今と新しい雛形で対に撃つ。
  - その形を入れると PASS の memo の道と質の項が涸れる。→ 入れる時に口と項を向け直し、撤退の数えを前後で分ける。
  - 詰めの線を上限の手前に置く形が、持ち主の決めた上限の見直しに読める。→ 詰めの線を外し、上限と詰め方は替えない。
- 軽い 8（決定の字・数えの開示・定数の共有・撃ち直せない時の扱い・題の字・平均の字・雛形の 1 文の副作用・掃除の容量）は第 3 版に映した。
