## 2. 置き替えは無駄を止めるか

- S2（問う・D）便ごとの同じ本文の門の逃げ。鍵は本文の字句の hash なので、関数の名替えと base の物の写しは落ちる（D・よい）。逃げは: (i) 写した本文の局所の名を替える（字句の hash は識別子を含む）、(ii) 1 字（定数・式の並び）を替える、(iii) 閉包・大きな関数の中・macro の本文へ写す、(iv) 3 行未満、(v) proc-macro2 の形では入れ子の item に doc の注を足す（doc の注が #[doc] の token になり hash が替わる・I）。3 種の外に残る無駄の型（名だけ替えた近い複製・同じ事をする別の作り・使われるが要らない機能の足し）は、総量の上限が無い間は人の審査（条 P-27 の機構・human-review）と整理の memo の file の大きさの上位 20 だけが見る。甲の失う物は「無駄でない新しい機能・長い doc の注」だけを書き、この型を書いていない。足しの案: 夜に識別子の番号替えの hash（r421 の ident の列・3 行の床で exact の外に 18 組・誤りを含む・r421 notes §3）を前の夜との差の検出線で回す（5 秒・依存 0・I）。
- M6（直す・D）撤退 (2) の鍵の後ろ半分「便ごとの門を通って着地した後に夜に拾った同じ本文の組」を測る者が (4) に無い（夜の検出線は SCIP の (a)(b) だけ）。また差の形は並んだ 2 便に逃げる: 便 A が f を、便 B が同じ本文の g を足すと、どちらの base にも組が無いので両方通り、着地の後に組ができる（tsuzuri の便と器の便は並んで流れる・D）。直し: 夜に同じ本文の hash を前の夜との差で撃つ段を (4) に足すか、撤退 (2) の鍵から後ろ半分を外す。
- S4（問う・V と D）pub(crate) に狭める 1,760 本。数は 9c398a5b の物で、その後 .14・.19・.20 が core を替えた（I・撃ち直しが要る）。大きさ: 99 本の patch が 49,842 byte（r421 の narrow-cand.patch・V）→ 1,760 本で約 0.89 MB（線形の D）→ diff の線 150,000 byte で 6 便以上、器を書く便は同時に 1 本なので器の線に直列で並ぶ。別の crate を壊さない照らし: r421 の 2 つの試しの lint は dead_code と unused_imports だけ（narrow-check.jsonl 6,338・15、narrow-cand.jsonl 70・3・V）で、一部だけ狭めた時に pub のまま残る 588 本の型の面に狭めた型が出る private_interfaces（既定 warn・-D warnings で落ちる）は試していない（U）。また以後の便が足す item を pub で書けば rustc は見ない（決定 (4) の「以後は rustc の dead_code が新しい無駄を落とす」は pub(crate) で書かれた物だけ）。module の可視性で狭める形（pub(crate) mod と再輸出）なら新しい item も rustc の目に入るか、を比べに足すか問う。
- ok（D）夜の索引の当たりが memo になるだけで止めない費え: 外から見える pub の無駄が最大 1 日着地する。甲の失う物に書かれている（V・ADR-80.yaml:53）。
