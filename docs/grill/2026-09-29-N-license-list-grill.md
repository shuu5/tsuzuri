## 3. 総合の判定

- **(甲) のまま: 不支持**（三条項の条件を足す部分）。緩める利益の主張が耐えず、同意の前提が誤っている。
- 主の形は (乙)、副は (甲)（決め直しの問い t3-hub.67.30 の答えしだい）。
- **(乙): 支持**。条件は次の 5 つ。
  1. 決め直しの問い t3-hub.67.30 の答えを、判断の記録の承認の欄に足す（2 節）。答えの記帳で O2 の正しい数を notes に書く。
  2. G2 の食い違いを「過去の漏れの訂正」として判断の記録の文脈に分けて書く（利益として数えない）。
  3. 一覧の範囲（build・dev・全部の target）を population の欄に書く（G3）。
  4. 撤退条件 (1)(2) の数え方と数える時を名指す（G9）。監査の便の置き場か、それまでの手の評価を書く（N3）。
  5. encoding_rs が黙って戻らないように押さえる（O1）。

## 4. 人の審査にしか見えない穴（機械は見ない）

1. CI の監査（cargo deny）が置かれるまで、R-2 の一覧は床も CI も見ない。持ち込みの時と依存の増減の時に、席が手で式を評価する。
2. 部品の中身の許しの file に、欄の式に無い義務が在るか（撤退条件 (3)）。今回読んだのは encoding_rs と foldhash だけ。
3. 面の wasm や組み立て物を、持ち主の端末の外へ配り始めた時に、決定 (5)（表示を写す仕掛け）を起こすか。配り始めたことを知らせる仕掛けは無い。
