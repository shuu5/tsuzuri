## 2. 器の数え

- 器の xtask は crates/*/src の下だけを数え、tests/ と build.rs は数えない＝正しい。
- 検査と本体の切り方と、比を全部を合わせた 1 つで比べること＝正しい。
- 受付の余地の検査は crates/<c>/src/ の形だけを見る（範囲の外の tests/ 等は門の対象外で測らない）＝正しい。folio2/crates/folio と tsuzuri の根の xtask/src は受付の数えに入らない。
- 案 A の足す字「member の src」は、器（dir の形で選ぶ）と xtask/ の扱いが違うので「器と同じ範囲」は小さな言い過ぎ。技術の段に「器の受付の余地は crates/<c>/src/ だけを測るので、xtask/ と folio2/ は数える段だけが測る」を足す。

## 3. 案の効果と推奨の釣り合い

- (1) 器の code の持ち込み（重い抜け）: 判断の記録 ADR-18 の決定 (5) と R-4 の population から、範囲の答えは器の code にも効く。器 main 7416928c を同じ式で数えた: 本体 73,592・src の中の検査 34,623・tests/ 65,906。案 A の比 0.47（内）・案 B の比 1.37（越える）・src の下の最大 1,490・tests/ で 1,500 行を越える file 16 本（最大 3,685）。案 C の「割る直し 1 回」は今の tsuzuri だけ（stcli.rs を 2 つに割る）。全体では folio を数える段で face_adr.rs（1,501）を割る（check.rs は 1,499 で余地 1 行）・器の持ち込みで tests/ の 16 本を割る。
- (2) 釣り合い: 案 A が数えるのは検査の code 108,024 行のうち 1,564 行（1.4%）だけ。比 0.033 は上限の 30 分の 1 で tsuzuri では比がほぼ縛らない（器は 0.47 で効く）。
- (3) 案 A の穴: 規則の行 R-1〜R-34・D-1〜D-4 に tests/ の file の行数を直接縛る行は無い。間接に効くのは関数の行数の lint（行 k-lint-tests が検査の関数にも掛ける・未着地）と R-5（CI 5 分・検出だけ）の 2 つ。
- (4) 持ち主の手間: 案 B と C では器の受付が tests/ を測らないので、越えは便を走らせた後の検査で落ち、やり直しになる。
- (5) 案 A に埋まった決め 4 つ: 比は全部を合わせた 1 つ（部品ごとだと xtask が 1.19 で越える）・1 module は file の全体（検査の区間も含む）で数える（今の足す字から読めない）・build.rs は数えない・数えるのは workspace の部品で除外の表が名指す持ち込みの code は表の行が消えるまで数えない。
