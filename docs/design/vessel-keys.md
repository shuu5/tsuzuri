# vessel-keys — 器の既定の置き場に置く契約表（vessel 宣言の key を書く行）

tsuzuri の契約表は、設計ノート（design-intent/design-note/）から導く contracts/ の toml に置くのが決まりの形である。
この文書だけは例外で、器 scribe2 の既定の置き場（docs/design/ の直下の .md）に契約表を直に置く。

## 1. 目的（この文書を置く理由と退かせ方）

器の行 cg が binary に入ると、受付は vessel 宣言の置き場の外を指す契約の pointer を断る。tsuzuri の契約の pointer は contracts/ の toml を指すので、vessel 宣言に key contract-tables を書く要がある。key は .vessel.toml にしか書けず、席は .vessel.toml を書けない（器の権能の門が code の種別と読む）。受付は base の宣言を読むので、key を main に置くには便が書く。この行は key を書く前に流すので、key が無くても断られない器の既定の置き場に置く。

便の契約 bead の受入の条件は design = docs/design/vessel-keys.md#v-field-schema の 1 行。行は設計ノートの索引に無いので、tz の索引の design の辺は組まれない（tz graph --check の g-2 は pointer の行が 1 つであることだけを数える）。着地の後もこの文書は消さず、着地済みの契約の記録として残す（廃止した設計ノートの toml と同じ扱い）。この文書に新しい行を足さない。

## 2. 器の契約表の置き場の宣言 — 契約表の欄の写しを contracts/ の直下から下の dir へ移し、vessel 宣言に key contract-tables と constitution を書く（行 v-field-schema）

在りか。差を切った main は 5b1099ae。起草 w80a が main 5b1099ae の写しで試作した。書く file は write-set の 46 項（移す元 1・移す先 1・folio の src 4・folio の歯 35・folio2 の設計ノートの欄の決まり 1・fixture 3・vessel 宣言 1）。差の file docs/design/patch/v-field-schema.patch が字の正本（試作の差 55,949 byte・移す file は git の rename で類似 100%）。

なぜ。器 scribe2 の行 cb〜cg（器の設計 contract-source.md の 69 節・器の判断の記録 ADR-0109）で、vessel 宣言の任意の key contract-tables が契約表の置き場を名乗る。末尾が / の項目は dir で、器の読み手はその dir の直下の .md と .toml を全部契約表と読み、下の dir は読まない（69 節の形 1 と限界）。tsuzuri の契約表は contracts/ の直下の <ノート>.toml で、同じ dir に契約表の欄の写し contracts/schema.toml（[[field]] 18 と [[promise-field]] 9 の表）が在る。key に contracts/ を書くと器の読み手がこの file を表と読み、未知の section [[field]] で読めない（main 5b1099ae の写しに key を書いた器の contracts check は findings 654・うち 465 がこの file の読めない）。器の行 cg が binary に入ると、受付は宣言の置き場の外を指す契約の pointer を place-outside で断るので、tsuzuri は key を書く要がある。この行は欄の写しを下の dir へ移し、folio の読む置き場を合わせ、同じ差で vessel 宣言に key を書く。移した後の木に key を書いた写しの contracts check は findings 189（着地済みの古い行の write-set の項目の解けない 169 と、歯の file が write-set の外 20・どちらもこの行は増やさない）。

置き場（この契約表）。この行は tsuzuri の設計ノート（contracts/ の toml）でなく、器の既定の置き場 docs/design/ の直下の .md の契約表に置く。key を書く前は contracts/ の toml を指す pointer を器の行 cg が place-outside で断り、key は .vessel.toml にしか書けない。席は .vessel.toml を書けない（器の権能の門 role_guard が .vessel.toml を code の種別と読み、席の役割は code の編集の権能を持たない）。受付は base の宣言を読むので、key を main に置くには便が書く要がある（器の席 scribe2-63 の推奨の形・器の受付に宣言の file を名指して断る規則は無い）。既定の置き場の .md の契約は key が無くても cg が断らない。

形（移す先）。移す先は contracts/ の下の dir contracts/field-schema/。器の dir の項目は直下だけを読むので表と読まれない（器の 69 節の歯 (c) が contracts/sub/f.toml を返さないことを測る・写しで key を書いて撃った findings は 189 で、contracts/ の外へ移した写しと同じ数）。contracts/ の外にしない理由は 2 つ。席の設計の commit の道具が設計の置き場の外の差分を断り、contracts/ の下はその内にある（器の版上げで欄の写しを写し直す時に道具を替えずに済む）。面の server の裁定の書き出しの持ち回しの印が contracts/ の下を深さを問わず歩く（外へ出すと印から落ちる）。file の名と byte は替えない。folio の歯の材料の写し folio2/contracts/schema.toml（歯の repo_root() の下・器の読み手の置き場の外）は動かさない。

形（folio）。床の定数 EXTERNAL_PATH（folio2/crates/folio/src/floor_note.rs）を contracts/field-schema/schema.toml にし、その doc の注に理由の 1 行を足す。derive の口の --dir の help の字（entry.rs）は新しい path を名指し、face_note.rs と note.rs の module の注は字の path でなく定数の名 EXTERNAL_PATH を名指す。設計ノートの欄の決まりの生成区間の字 path（folio2/design-intent/design-note/schema.yaml と fixture の floor_base の schema.yaml と schema/note-region.txt）を新しい path にする（13 byte 増・行の数は同じ）。folio の歯は、一時 dir の根の下に器の導出 file の写しを置く所（写す先）と、その親の dir を作る所と、字を断言する所（f119_ の derive の読めない・f121_ の凍結しない・f192_ の版管理の無い根・f154_ の入れ子の根）と注だけを新しい path にし、写す元（repo_root() の下の歯の材料の写し）の字は替えない。tests/resolve.rs は定数 EXTERNAL を新しい path にし、写す元の定数 REPO_COPY を足し、歯 fsch_ を 3 本足す（根の写しは形だけを見て、歯の材料の写しと字を比べない・器の版上げで席が根の写しだけを写し直せるように）。3 本目は vessel 宣言の 2 つの key の行を見る。凍結の値は前例（便 196 ほか）と同じ形で動かす。tests/schema.rs の NOTE_REGION_BYTES を 21439 に、NOTE_REGION_SHA256 を新しい要約値にする（tests/schema.rs は歯 f89_ の器の式〔1 行の字 120 ごとに 1〕で上限 700 ちょうどなので、注の字を足さず値だけを替える）。tests/graph.rs の F99_ANCHOR_SHA256 と土台の anchor node-digest-anchor.txt の残差の 2 行を、独立の実装 node-digest.py の出力で書き直し、注を 1 行足す（anchor の byte 数 3082 と行の数 197 は同じ）。

形（vessel 宣言）。.vessel.toml の末に、器の任意の key 2 つと注を足す。contract-tables = [contracts/] の 1 行（注に器の判断の記録 ADR-0109・器の行 cb〜cg・器の設計 contract-source.md の 69 節）と、constitution = [design-intent/constitution.yaml, design-intent/rules.yaml] の 1 行（注に器の判断の記録 ADR-0110・器の行 as）。値の配列の項目は .vessel.toml の中では二重引用符で囲む（差の file の字のとおり）。どちらの注にも持ち主の承認の裁定 id t3-hub.74.29:20261002T2330Z-1 を書く（持ち主の逐語は書かない）。key constitution が効くと、器の審査役は既定の docs/constitution.md の代わりに 2 file を読む。案内の docs/constitution.md はこの行で消さない（審査役が 2 file を読むのを gate で見た後の別の手）。PATH の器の binary（07b7f298）は 2 つの key を読む（写しで撃った契約表の検査と受付の前の点検が rc 2 にならない）。

実装の約束。便は差の file を git apply で当てるだけで、差の外の字を 1 字も書かず、差の file も書き替えない。当たらない時は手で書かずに止まる。

done と verify の対応。(1) は verify の 1 行目。(2) は 2 行目。(3) は 3 行目の fsch_。(4) は 4 行目の f123_。(5) は 5 行目。(6) は 6 行目。(7) は 7 行目。(8) は 8 行目。(9) は 9 行目。xtask の check（10 行目・器の共通 verify）は folio の歯を全部撃つ。

構造の連鎖。EXTERNAL_PATH を引くのは床の読み手（note.rs の external_path・版管理の根の下）と面の生成器の読めないの字（face_note.rs）と提案の写し（proposed.rs・写しの親の下の同じ字の所へ写す）と床の定数の生成区間 FLOOR（tz schema --write の字）で、どれも定数を引くので src の字の path は定数の 1 か所だけ。tz の derive・check・schema・face・proposed の口の引数と終了 code は変わらない。folio derive の置き場の直下の導出元の無い .toml の数え（数えない の行）からは、移した後の main で schema.toml の 1 行が消える（導出物の 83 file の一致は同じ）。

試作と噛み。main 5b1099ae の写しにこの差を当てた木で xtask の check が rc 0（歯 3,026 本）。verify の 10 行を 1 行ずつ撃って全部 rc 0。写しの根の床（試作の tz で schema --write・derive --write・check・derive --check）は、schema --write が根の design-intent/design-note/schema.yaml の path の 1 行を書き直した後に、check 合格（違反 0）・derive --check 一致 83。差の file は main 5b1099ae の床の写しで git apply --check が rc 0、試作の木で git apply --reverse --check が rc 0。変異 8 つ（床の定数を前の path に戻す・根の contracts/ の直下に欄の写しを戻す・床の読み手が新しい path に無い時に前の path を読む・folio2 の欄の決まりの path を前の字に戻す・移した写しの欄を 1 つ消す・凍結 anchor note-region.txt の path を前の字に戻す・土台 floor_base の欄の決まりの path を前の字に戻す・vessel 宣言の key contract-tables の行を消す）を 1 つずつ当て、どれも done の歯が落ちた（fsch_ は 2 つ目と 3 つ目と 8 つ目の変異をそれぞれ 1 本だけで噛む）。器の受付の前の点検は、この .md の契約表を置いた main の写しで、この行が器の今の binary と行 cg 入りの binary の両方で ok。差を当てた後の木（key 入り）では、ほかの行（試しの toml の行）が両方の binary で ok。

filter の語。新しい歯の接頭辞 fsch_ は、main 5b1099ae の契約表の verify の filter の語 403 語のどれとも部分の字として重ならない。f123_ と check_canonical_design_intent_passes は着地済みの語。

着地の後（席の手・範囲の外）。(a) 席の道具の pin（tz と folio）を着地の後の main で組み直して替える。前の pin は欄の写しを前の置き場で探し、床が まだ分からない で止まる（写しで撃った: 前の tz の pin の check と derive --check が rc 2）。(b) pin を替えた後の最初の設計の commit で、tz schema --write が根の design-intent/design-note/schema.yaml の生成区間の path の 1 行を書き直す（この行は根の design-intent を書かない・新しい pin で schema --write の前に撃つ check は違反 1）。(c) 着地で key が効き、器の見張り（契約表の検査・局面の行・台帳の形・live-row の門）が contracts/ の toml を読み出す（写しの契約表の検査は findings 189 と、この .md の行の移す元と移す先の 2 つ）。その後に器の席が行 cg 入りの binary へ入れ替える。(d) この .md は着地の後も消さずに着地済みの契約の記録として残す（tsuzuri の廃止したノートの toml と同じ扱い）。

範囲の外。docs/constitution.md を消すこと・根の design-intent の欄の決まりの生成区間・席の道具の pin・欄の写しの中身を器の今の欄（done-teeth と code-facts を足した 20 欄）に写し直すこと（別の行）・folio2/design-intent の散文と判断の記録と要件書の字（記録の歴史）・folio2/contracts/schema.toml の置き場・面の server の印。
