生成物・手で直さない・design-intent/constitution.yaml v1.5
順位 段どうしが衝突したら「絶対にやらない ＞ 確認してから ＞ いつも守る」の順で解き、条どうしが衝突したら「場当たりの修正の禁止 ／ 黙らないこと ／ 戻せること ／ 増殖の防止 ／ compile の速さ」の順で解く。
P-1.1 規則・閾値・型の一覧は型付きデータ（正本 YAML・規則の表の行・宣言 file（manifest）・実装の型付きの定数）に置く。
P-1.2 文書と台帳からは、規則を id で参照する。
P-1.3 台帳はタスクと裁定の記帳先であり、規則を置かない。
P-1.4 原則と裁定の正本は設計文書、機械が執行する規則の正本は型付きデータとし、置き場をこの 2 面に限る。
P-1.5 実装の型付きの定数を規則の正本とするあいだ、その写しを人が読める型付きデータとして設計文書の置き場へ決定的に導出する。
P-1.6 規則の種類は閉じた 1 つの型の枝（variant）として表し、網羅の検査を持ち、新しい理由は新しい枝としてだけ足す。
P-1.7 読み手の無い設定の行を検査が記録し、落とす門へ上げるのは裁定 id つきのときだけにする。
P-2.1 設計文書の正本は YAML の 1 file であり、人が読むページも席へ渡す写しもそこから逐語で生成する。
P-2.2 生成物を手で直さない。
P-2.3 同じ内容を 2 つの面が持つとき、一方を正本とし、他方は導出する。
P-2.4 2 つの面を人が書き、一致を検査で強制する設計を採らない。
P-3.1 要件・条文・判断・受入基準・契約の id を再利用・改番しない。
P-3.2 廃止は状態（status）で表し、番号は空けたままにする。
P-4.1 取り消しにくい判断（判断の記録）には、それを捨てる条件を同時に書く。
P-5.1 v3 の開発を拘束するのは設計文書（design-intent）である。
P-5.2 前の版（scribe2・folio2）を、受入の物差し役にも停止権の持ち主にもしない。
P-5.3 設計文書の変更は、判断の記録か版付きの文書として残す。
P-6.1 機械で決定的に検査できる項目は床に置く。
P-6.2 意味の検査（読みやすさ・忠実さ・契約の審査）は AI の天井に置く。
P-6.3 床の合格を、完成や天井の合格として扱わない。
P-7.1 検査・生成・便の実行ができなかった結果を「異常なし」として扱わない。
P-7.2 判定できないものは「まだ分からない」として表に出す。
P-7.3 断るときは何を断ったかと次の 1 手を名指す。
P-8.1 宣言した値・出所つきで測った値・導出した値・効いている値を型で区別する。
P-8.2 宣言した値を効いている値へ昇格させるのは測定を通したときだけとする。
P-8.3 器と道具は、報告と一覧を、手で書いた要約からでなく正本と記録から導いて出す。
P-9.1 検査は、生成側からも検査側からも独立した凍結 anchor（固定の fixture）を 1 本以上持つ。
P-9.2 生成物どうしの突き合わせを唯一の合格判定にしない。
P-9.3 anchor が維持できなくなった検査の結果は「まだ分からない」に落とす。
P-10.1 同じ種類の失敗が規則の表の行 R-3 の回数を超えたとき、自動の修正を続けず、止めて持ち主へ渡す。
P-11.1 席が止まったとき、器は人手を待たずにそれを検知し、席の仕事を再開し、その結果を保つ。
P-11.2 便の終端は札の不在で推さず、終端の記録（event）で持つ。
P-12.1 持ち主の承認は、規則の表の行 R-8 が指す 1 つの対話面を通ったものだけを受け取る。
P-12.2 受け取った承認は、逐語と日付と裁定 id を添えて台帳の記帳と文書の承認欄に残す。
P-12.3 会話の記憶を承認の根拠にしない。
P-13.1 注入の命令を実行したとき、憲法の前文の順位と、段「絶対にやらない」と段「確認してから」の規範文の全文と、全文の写しの在りかと、規則の表の作法の行の id と what と、席の役割の指示文を、この順で席の手元の生成区間へ決定的に導出して書く。
P-13.2 注入の検査は生成区間と正本の差分を検出し、差があれば失敗で終える。
P-13.3 生成区間の総バイト数は規則の表の行 R-1 以下に収める。
P-14.1 編集が設計文書か契約か規則の表と食い違うとき、その編集を編集の時点で止める。
P-14.2 事後の検査を、編集の時点で止めることの代わりにしない。
P-14.3 止める仕掛け（guard）は「開く／閉じる」の極性と「編集時／事後」の別を型で持ち、その一覧（極性一覧）を生成時に出す。
P-14.4 編集の時点で止める guard が 1 本も無い構成なら、検査がそれを落とす。
P-15.1 自動で走る仕掛け（hook）を「守られる保証」として設計しない。
P-15.2 編集の時点で止める仕掛けを持つときは、その判定の式を事後の検査が同じ関数で確かめる。
P-16.1 席ごとの AI モデルと念入りさは、要件書の制約で名指す。
P-16.2 道具（並列実行・便・作業者）の内側には最上位のモデルを求めない。
P-16.3 込み入った設計判断では、持ち主が選んだモデルで動く相談の窓の所見を材料にできる。
P-17.1 規則の表（R-n・D-n）の行の追加・変更は、裁定 id と時刻を行に付ける。
P-17.2 裁定 id の無い規則の表の行の変更があったら、検査がそれを落とす。
P-17.3 初版の行は、この憲法の発効の承認を裁定とみなし、発効時にその id と時刻を全行に付ける。
P-17.4 振る舞いを縛る閾値行（deny 種別）の値を緩めるとき、A-2.3 の検証を前置する。
P-18.1 設計文書の人が読むページはすべて 1 つの生成器から出力する。
P-18.2 手書きのページを配信先と入口の導線に置かない。
P-18.3 色・字の大きさ・余白の元の値（design token）は 1 か所で定義する。
P-18.4 部品・図の型・密度 profile は閉じた一覧（部品目録）で持ち、追加には判断の記録を要する。
P-19.1 道具は文書を生成し、機械で検査し、結果を知らせるところまでを担う。
P-19.2 道具と器は要否・採否の最終判断を代行する機能を持たない。
P-20.1 host・口座・席・貸出・退役の状態は host の列を持つ 1 つの database file に置く。
P-20.2 host ごとの dir・TSV・cache に真実を置かない。
P-20.3 器は席の状態を描画からでなく構造（hook・状態 file・SDK の口）から読む。
P-20.4 器は口座を割り当ての窓の終わりまで使い、選び方は規則の表の行で持つ。
P-20.5 器と道具は、席の状態を、自由文の字面からでなく型の列挙か形を検査した記録の行から判じる。
P-21.1 選定・除外・経路づけはそれぞれ 1 つの列挙（enum）の上の 1 つの関数として実装し、適用の順は段の列挙の宣言順だけから取る。
P-21.2 順序についての散文の注を持たない。
P-21.3 完了の条件は 1 つの列挙の値だけで表し、待つ実装を 1 つにする。
P-21.4 任意の条件の関数を受ける待ちの口を持たない。
P-22.1 core の総行数・module の行数・歯と source の行数比・関数の粒度の上限（規則の表の行 R-4）を CI が実測する deny の門として持つ。
P-22.2 粒度の lint を allow の属性で黙らせない。
P-22.3 上限の変更は A-2 だけを通す。
P-23.1 予算（Budget）は事前の実測（Precheck）を消費してしか作れない型とする。
P-23.2 席や便を起こす口は 1 つだけとし、その口は予算を要る。
P-23.3 消費は 1 つの追記だけの記録に残す。
P-24.1 規則の表の行 R-10 の一覧にある書き方（unwrap・expect・panic・todo・unimplemented・unreachable・process の exit・slice の添字・debug の macro・直接の stdout と stderr）を workspace の lint で deny にする。
P-24.2 unsafe な code を禁じ、使わない must-use の値を deny にする。
P-24.3 lint の例外は書いた理由を持つ expect の属性だけで許し、歯の範囲の例外は lint の設定で宣言する。
P-24.4 時間切れは呼び手に分岐を強いる型で返す。
P-24.5 core に型の無い error を置かない。
P-25.1 歯（test）は Rust の 1 つの枠組みだけで書き、shell の歯を持たない。
P-25.2 外形（命令の出力・生成した文書・極性一覧）は凍結した写し（snapshot）で守り、参照されない写しは落とす。
P-25.3 変異生存率は規則の表の行 R-9 の間隔で記録し、deny への昇格は裁定 id を伴う持ち主の裁定だけで行う。
P-25.4 落ちたままの歯の台帳（KNOWN-RED）を持たない。
P-25.5 変更は落ちる歯から始め、歯の差分だけを base に当てると落ち、HEAD で通ることを検査が確かめる。
P-25.6 歯の差分を持たない変更は、文書だけの面の変更でなければ、検査が落とす。
P-25.7 main の先端が測り直しても赤なら、戻すか直す取り込みを次の取り込みより先にする。
P-26.1 依存は許可の一覧と予算（規則の表の行 R-2）で管理し、追加は予算の範囲で持ち主の確認（A-3）と増分の compile 時間の実測差を添えて行う。
P-26.2 derive の macro は境界の crate に閉じ、機能の全部を有効にする指定を使わない。
P-26.3 core は非同期（async）の実行系を持たない。
P-26.4 compile の秒数は規則の表の行 R-5 の検出線として記録し、悪化したら原因の crate を名指して起票し、取り込みは止めない。
P-26.5 依存の重複した版・脆弱性・使ってよい条件（ライセンス）を CI で監査する。
P-27.1 変更を提案・実装するとき、決定はしご（要るか → 既に在るか → 標準 library か入っている依存で足りるか → 1 行で書けるか → 最小実装）をこの条に書いた順に通り、最初に成立した段で止まる。
P-27.2 走査・記録・規則の表の行・仕掛けを足す提案は、先に消すものを名指す。
P-28.1 設計ノートの中身を要件か判断の記録かほかの設計ノートへ移したとき、または全部の契約表の行が着地したとき、後継を名指してそのノートを廃止の状態にし、設計ノートの置き場の直下に残す。
P-28.2 下書きか発効の状態の設計ノートの本数と、ノートごとの契約表の行の数と、それらの計画だけの行の数の合計に、規則の表の行で上限を置き、床が数えて越えたら落とす。
P-28.3 上限の値を緩めるとき、退役か統合で数を減らせない理由を、前置する検証（P-17.4）の記録に書く。
P-28.4 契約表の行を持つ設計ノートを、見本の状態に置いて、または設計ノートの置き場の直下から動かして、上限の数えから外さず、開いた契約表の行を持つ設計ノートを廃止の状態にしない。
P-28.5 全部の契約表の行が着地した設計ノートは、廃止にするまで検査が名指し、規則の表の行が猶予を置くときは猶予を越えたものを落とす。
A-1.1 既存の文書やデータを消す、外へ出す、外部の道具や鍵を使う（課金を含む）操作を行うとき、実行前に規則の表の行 R-8 の対話面で持ち主の確認を得る。
A-1.2 得た承認は逐語を添えた承認の記録（event）として残す。
A-2.1 条文を改訂するとき、判断の記録と撤退条件を先に書き、持ち主の承認（逐語・日付・裁定 id）を得てから版を上げる。
A-2.2 条文（id・見出し・規範文・段・縛る相手）と schema 節・前文が 1 文字も変わらない変更を改訂として扱わない。
A-2.3 改訂の前と、大きさの上限（R-4）と依存の予算（R-2）の閾値を変える前に、その変更が主張する利益を敵対的に検証し（grill）、記録を判断の記録に添える。
A-3.1 外部ライブラリを増やす・減らすとき、予算（規則の表の行 R-2）と使ってよい条件（ライセンス）に照らし、持ち主の確認を得る。
A-4.1 器と道具が自分自身の文書・code を変える運用は、既定で許可する。
A-4.2 その操作が取り消せない（消す・出す・使う）とき、A-1 として持ち主に確認する。
A-4.3 取り込み（merge）・自分の repo への便の起動・外部依存を増やさない変更は、A-4.2 の判定で「取り消せる」と扱う。
N-1.1 操作が管理下の対象を回復不能に削除するなら、器と道具はそれを拒む。
N-1.2 退役（廃止）は可逆な移動としてのみ行う。
N-2.1 変更が、散文・記憶・会話にしか無い規則を持ち込むなら、それを規則として扱わない。
N-2.2 変更が、散文・記憶・会話にしか無い規則を持ち込むなら、検査がそれを落とす。
N-3.1 変更が規則の例外機構（無効化の旗・「今回だけ」の口）を足すなら、それを拒む。
N-4.1 条文の改訂が、判断の記録・裁定 id・承認の逐語のいずれかを欠くなら、それを拒む。
N-4.2 同じ版の中で schema の互換を壊す変更があったら、それを拒む。
N-5.1 変更が文書の型ごとの AI 係（agent）や検査の観点（lens）を増設するなら、それを拒む。
N-5.2 変更が app ごとの表示の仕組みを増設するなら、それを拒む。
N-6.1 配信（serve）と表示 server の接続先（bind 先）が、同じ端末の中（loopback）でも tailnet の中でもないなら、起動を拒む。
N-6.2 配信の出力と、台帳と設計文書の中身を、認証なしの公開ネットに晒さない。
N-7.1 code が host 固有の値で分岐するなら、それを拒む。
N-7.2 host ごとの値は宣言 file（manifest）に置く。
N-7.3 core は環境変数を直に読まない。
N-7.4 core は設定を宣言 file からだけ読み、名から導く字（plugin・crate・state dir・環境変数の頭・端末の多重化の server の名）を名の定数から導く。
