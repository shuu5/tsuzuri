憲法›00 北極星 1/9

北極星

何のために・誰のために・何をあきらめるか

「なぜ作るか」はここに吸収する（別の文書にしない）。迷ったときは、この 3 つに戻る。

はじめて読む人 1/3入口の「読む順番」で選んだ道のうち、「はじめて読む人」の 1 番目。次は要件書 §1、その次は要件書 §3 の図 2。次は → 要件書 §1 ゴール

北極星（1 文）

非エンジニアが AI と相談しながら、必要な設計文書だけを、同じ見た目で迷わず持てる

達成の判定は 要件書 §5 受入基準 で行う。

誰のため

持ち主（非エンジニア）と、それを読む AI

同じページを両方が読む。人には「やさしく言うと」、AI には「機械のための面」。

迷ったらどちらへ倒すか

網羅より揃い ／ 速さより黙らないこと ／ 賢さより戻せること

左を捨てて右を取る。順序も固定。

01

憲法›01 読み方 2/9

読み方

3 段の意味 — いつも守る・確認してから変える・絶対にやらない

条文は 3 段に分かれる。段は「外し方」で分かれる。『いつも守る』と『絶対にやらない』を外すには憲法の改訂（判断の記録 ＋ 持ち主の承認）が要る。『確認してから変える』だけは、その場の持ち主の確認で足りる。

いつも守る（Always）

道具も AI も、毎回これに従う

道具も AI も例外なく従う。

外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認）

確認してから変える（Ask-first）

やってよいが、実行前に持ち主へ確認する

やってよいが、やる前に持ち主へ聞く。

外すのに要るもの: その場の持ち主の確認

絶対にやらない（Never）

確認があってもやらない

確認があってもやらない。v1 で実際に壊れた作りを繰り返さないための線。

外すのに要るもの: 憲法の改訂（確認では解けない）

補足

各条は「正確な条文（用語 · MUST / MUST NOTMUST = 必ず守る。MUST NOT = 決してしない。SHOULD = 強い推奨（外すなら理由が要る）。条文の中で赤く出る。 用語集で見る → 入り）→ やさしく言うと → 根拠・関係・撤退条件」の順。いちばん下の「機械のための面」は、上に出ていない項目だけを AI 向けに残した短い表で、人が読むときは開かなくてよい。

憲法›02 いつも守る 3/9

いつも守る

8 つの原則

道具の作り方と、文書の持ち方の両方にかかる。この章の 8 条はすべて「いつも守る」段。

作る人 1/3次は → §6 変えるときの手続き

P-1

判断する道具を作らない

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

folio は「生成する・機械で検査する・知らせる」までを担い、要否・採否の最終判断は人間が行う。folio が判断を代行する機能を持っては MUST NOT ならない。

やさしく言うと道具は、書類を作って、間違いを見つけて、知らせるところまで。「これでいいか」を決めるのはあなたです。

v1 の教訓「判断する engine を作らない」（報告 §2（報告・tailnet 内））要件書 FR2（答えが無くても止まらない）と衝突しない線は裁定 #1（推奨で進み、支度表で覆す）

P-2

提示層は単一の生成器が所有する

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

人が読む HTML はすべて 1 つの用語 · 生成器生成物 = 正本から機械が作ったもの（手で直さない）。生成器 = それを作る係。 用語集で見る →から出力される MUST。手書きの HTML を配信先と入口の導線に置いては MUST NOT ならない。用語 · design token色・字の大きさ・余白などの元の値。1 か所で決めて全ページが使う。 用語集で見る →は 1 か所で定義する。

やさしく言うと見た目を作る係は 1 つだけ。誰かが手で HTML を書き足すと、そこから見た目が割れていくので、入口からも締め出します。

v1 で見た目が 3 系統に割れた原因は「所有者が 2 つ」（報告 軸 5）要件書 FR4・NFR2 がこの条を数で確かめる

改訂来歴裁定 #4 2026-09-12 · v1 の P-2「format は HTML + common.css のみ」を置換（§6 に例）
P-3

検査は二層 — 機械の床と AI の天井

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

機械で決定的に検査できる項目は用語 · 床（floor）床 = 機械が決定的に検査する層（合格は「壊れていない」の意味）。天井 = AI が意味を検査する層。 用語集で見る →として実装し、意味の検査は AI の天井（ceiling）に置く MUST。床が緑でも「完成」を意味しない（床の緑 = 検査基盤が健全な範囲で緑）。

やさしく言うと機械が数えられること（部品が揃っているか等）は機械が、意味（分かりやすいか等）は AI が見ます。機械の合格は「壊れていない」であって「良い」ではありません。

v1 の教訓「二層 enforcement」「floor 緑 ≠ 完成」（報告 §2）要件書 FR5（検査結果を必ず返す）

P-4

黙って飛ばさない（fail-closed）

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

検査・生成が実行できないとき、その結果を「異常なし」として扱っては MUST NOT ならない。受け入れる範囲を絞り、判定できないものは Pending として表に出す MUST（用語 · fail-closed確かめられなかったら「合格」にしない、という安全側の倒し方。 用語集で見る →）。

やさしく言うとできなかったことを「問題なし」に化けさせません。分からないときは「分からない」と表示します。

v1 の教訓「no silent skip」「受理域を絞る fail-closed」（報告 §2）要件書 FR5 と 図 3（検査の答えは 3 つ）

機械のための面（上に出ていない項目だけ）
verdict-enum
Pass | Fail | Pending（3 値・閉じた enum）
P-5

散文だけの規則は規則ではない

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

規則・閾値・型の一覧は型付きデータ（enum / profile / YAML）に置き、文書からは id で参照する MUST。CLAUDE.md や会話にしか無い規則に強制力を持たせては MUST NOT ならない。

やさしく言うと「こうしてね」と文章に書いただけでは、AI は守り続けられません。守らせたい規則は表に載せ、番号で呼びます。

scribe2 憲法 N2 の機構条を写す（裁定 #3）§5 rules（数値表）・要件書 FR6（憲法の注入）

P-6

正本は 1 つ、HTML は生成物

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

各文書の用語 · 正本元になる唯一のファイル。ページはここから作った写し。 用語集で見る →は YAML であり、HTML はそこから逐語で生成する MUST。生成物を手で直しては MUST NOT ならない。散文の枠は型付きの slot として正本と同期する。

やさしく言うと「元のファイル」は 1 つだけ。見えているページはそこから作った写しなので、直したいときは元を直します。

裁定 #4（正本 YAML・HTML は生成物）・v1 の教訓「逐語 extract は捏造リスクゼロ」憲法の改訂表現が YAML で表せないと分かったら（用語 · spike決める前に小さく試して測ること。 用語集で見る → 1）、憲法だけ二正本 + byte 束縛へ退避する

P-7

番号は増やすだけ（append only）

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

要件・条文・判断の id は再利用も改番もしない MUST NOT。廃止は状態で表し、番号は消さない。

やさしく言うと一度つけた番号は、消したり付け替えたりしません。「FR3 は廃止」と書いて、FR3 の番号は空けたままにします。

この段 · いつも守る道具も AI も、毎回これに従う。外すのに要るもの: 憲法の改訂（§6: 判断の記録 + 持ち主の承認） §1 で 3 段を見る →

あとから戻せない判断（用語 · ADR戻せない判断を、理由・退けた案・撤退条件つきで残す 1 枚。 用語集で見る →）には、その判断を捨てる条件を同時に記す MUST。

憲法›04 絶対にやらない 5/9

絶対にやらない

3 つの原則 — 確認があってもやらない

v1 で実際に壊れた作りを繰り返さないための線。

N-1

hook（自動の仕掛け）を保証と見なさない

この段 · 絶対にやらない確認があってもやらない。外すのに要るもの: 憲法の改訂（確認では解けない） §1 で 3 段を見る →

自動で走る仕掛け（用語 · hookある出来事のときに自動で走る仕掛け。便利だが、守られる保証にはならない。 用語集で見る →）を「守られる保証」として設計しては MUST NOT ならない。強制は検査と fail-closed で行う。

やさしく言うと「自動で止まるはず」を頼りにしません。止まらなかったときにも壊れない作りにします。

v1 の教訓「hook は保証でない」（報告 §2）

N-2

例外の仕組みを作らない

この段 · 絶対にやらない確認があってもやらない。外すのに要るもの: 憲法の改訂（確認では解けない） §1 で 3 段を見る →

規則の例外機構（override フラグ等）を増やしては MUST NOT ならない。逃げ道は正式に 1 本（§6 の改訂）だけ。

やさしく言うと「今回だけ特別」のスイッチは作りません。変えたいときは正式に変えます。

v1 の教訓「例外機構を作らず正式な逃げ道を 1 本だけ」（報告 §2）この条自体の逃げ道は §6 の改訂のみ。それ以外の経路が必要になった時点で、条文の設計が間違っていたと見なして改訂する

N-3

文書の種類ごとに専用の AI 係を作らない

この段 · 絶対にやらない確認があってもやらない。外すのに要るもの: 憲法の改訂（確認では解けない） §1 で 3 段を見る →

文書の型ごとに agent や検査 lens を増設しては MUST NOT ならない。差は汎用の lens と profile データで表す。

やさしく言うと種類が増えるたびに係を増やすと、AI が毎回読む説明文が膨らんで、遅く・高くなります（v1 では 36 係になった）。

反面教師「doc-type 別 agent 36 本」「Tier 1 注入の予算事故」（報告 §2）要件書 NFR1（常時注入の上限）・§5 R-1

rules

数値は条文に書かない — 表で持ち、確認してから変える

条文は動かさず、数値だけ表で変えられるようにする。ここの値は仮（spike の結果で確定）。いま持ち主が決める行は 0 ＝ 凍結 3・仮 2・未定 1。値を変えるときに持ち主の承認が要る。

決める人 3/3ここが最後。承認欄へ

状態:

凍結 = 値は動かさない（変えるなら承認が要る）／ 仮 = 値は入っているが確定前（spike の結果で決まる）／ 未定 = まだ値が無い

id何の数値か値決まり方状態
R-1AI へ常時渡す説明文の合計（agent と skill の名前 + 説明） AI が毎回読まされる「道具の説明文」の量に上限を置く≤ 2,000 字測り方を凍結してから再計測（spike 2）仮
R-2CLAUDE.md に注入する憲法の板の長さ AI の手元に写す憲法は、この行数までに収める≤ 100 行M2 で確定仮
R-3部品目録に無い class の数 ／ 色や字の大きさが token 由来の割合 どのページも、決まった部品と決まった材料だけで作る0 ／ 100%M0 受入条件凍結
R-4参照 id（要件・条文・判断）の未解決 「FR3 を見よ」と書いたら FR3 は必ず実在する0M0 受入条件凍結
R-5密度 profile と図の型の数（見た目の詰まり方と図の種類） 見た目の種類と図の種類は決まった一覧から選ぶ。足すときは記録が要る有限の一覧（図は 3 型）追加は ADR を要する凍結
R-6外部ライブラリの予算（直接 ／ 間接の本数・license の許可一覧） 他人の部品を何本まで使ってよいか、どの license なら可か未定cargo deny の実測後（spike 4）未定
補足

「60 分以内」「300k token 以下」のような時間・費用の数値はここに置かない（測る仕組みが別で、凍結できない）。

憲法›06 改訂 7/9

改訂

変えるときの手続き — 動かせないものを、どう動かすか

憲法は動かせない。動かすときは、差分として記録し、持ち主が承認し、AI の手元（CLAUDE.md）に再注入する。図 1 と下の手順は同じ 4 段を指す。

作る人 2/3次は → 要件書 §7 対応表

  1. 1
    理由を書くAI判断の記録（ADR）を 1 本起こし、撤退条件（P-8）も同時に書く。
  2. 2
    差分で表すAI消す文と足す文を対にして記録する（下の例）。条文の番号は変えない（P-7）。
  3. 3
    持ち主が承認する持ち主承認者と日付を残す（A-2）。

    版を上げ、再注入する機械CLAUDE.md の生成区間を作り直し、差分が無いことを機械が確かめる（要件書 FR6）。
