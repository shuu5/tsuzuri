- 条: P-5.1・P-5.6 / P-6.3・P-6.4 / P-4.1・P-4.2 / P-10.1 / A-2.2 / N-3.1
- 材料: docs/design/adr-11-survey.md §1-b（A9〜A11・A16）と §1′-1（値域 10 + 3 本）・docs/design/adr-11-grill.md（D-1・D-6）・本ノート §1 の実測（2026-09-20・main ac2fee9）。
- 位置: ADR-11 決定 (4)① は完了（便 47・天井の正本 第 3 版・便 48）。本ノートは ② の向きを決め、便を 3 本に割る。便ごとの設計文書と契約表の行は別 file（1 本目 = docs/design/delivery-49.md）。

## 0. 結論（先に）

1. 憲法の値域 10 本は **憲法の file が正本**（ADR-11 (3)(ア)）のまま、実装の側の手書きの写しを **組み立て時の導出**（部品目録と同じ型・build.rs が型を書く）に替える。実行時に読む形は採らない。
2. 便は 3 本。便 49 = 導出の土台と床の側の写し 2 本（判断の記録の床の撤退条件の種類・注入の強度）。便 50 = 面の生成器の表の鍵の列（値域 10 本ぶん）。便 51 = 規則の表の欄の決まりの節を (イ) の向き（実装の定数が正本・生成区間へ写し）に。
3. 「決まるまでのつなぎ」（面の生成器が集合の一致を数える）は **入れない**。本体が 2 便で入るうえ、最小の写しの fixture 23 本が値域の節を持たず、つなぎの検査はそれらを全部直さないと入らないため（§1 の 5）。
4. 下調べが「写し」に数えた A10（改訂の範囲の下限）と A11（対話面の行 id）は **写しではない** と判定し、動かさない（§3 の 2・3）。
5. 副産物の所見 1 件 = 床は憲法の各欄の値が値域に入っているかを数えていない（面の生成器が初めて落とす）。本ノートの範囲の外・別の bead に起票する。

## 1. 実測

1. 憲法の値域（design-intent/constitution.yaml の schema.enums）は 10 本 = tier 3・binds 3・pattern 5・strength 3・rationale_kind 3・mechanism_kind 4・mechanism_live 5・retreat_kind 3・stage 2・polarity 2。規則の表（design-intent/rules.yaml の schema.enums）は 3 本 = kind 4・status 3・stage 2（stage は憲法と同じ 2 値）。
2. 実装の側の手書きの写し（退役待ちの render.rs の 10 枚は除く）:
   - 床の側 2 本 = crates/folio/src/adr.rs の RETREAT_KIND（床の木 FLOOR に入り、判断の記録の欄の決まり adr/schema.yaml の生成区間へ出る）・crates/folio/src/inject.rs の STRENGTHS（注入が規範文かどうかを決める）。
   - 面の側 = crates/folio/src/face.rs の表 10 枚（TIERS・STRENGTH・PATTERN・BINDS・MECH_KIND・LIVE・STAGE・POLARITY・RATIONALE_KIND・RETREAT_KIND）と、同じ鍵をもう 1 度持つ表 2 枚（STRENGTH_MEANING・PRIO）、crates/folio/src/face_adr.rs の RETREAT_KIND。使う所は約 45 か所（face_constitution.rs・face_index.rs・face_srs.rs・face_adr.rs・face.rs）。規則の表の側は RULE_KIND・RULE_STATUS（順が file と違う = file は 仮・凍結・未定、実装は 凍結・仮・未定）。
3. 一致を数えている口は 2 つだけ: 床の撤退条件の種類（crates/folio/src/link.rs の関数 retreat_kind・長さと字面と順・違反の文言に「憲法が正・床の定数を直す」・凍結の歯 tests/fixtures/link/retreat-kind-drift）と、面の段（crates/folio/src/face_constitution.rs 154〜164 行・集合の一致）。残り 8 本は表引きが片方向に在るだけで、file の一覧そのものは誰も読んでいない。
4. 床（crates/folio/src/check.rs の check_constitution）は憲法の各欄の値が値域に入っているかを **数えていない**（id の形・空でない欄・重複だけ）。値域の外の値を初めて落とすのは面の生成器の表引き（Err）と注入（強度だけ）。
5. 憲法の写しの fixture は 24 本。値域 10 本を全部持つのは凍結した土台 1 本だけで、16 本は retreat_kind だけ・2 本は tier だけ・5 本は値域の節が無い。= 値域 10 本を床で突き合わせる検査は、23 本を直さないと入らない。
6. 組み立て時の導出は既に 1 本在る（crates/folio/build.rs・部品目録から型 4 つを OUT_DIR へ書く・便 13）。導出した型は ALL・name・from_name を持ち、実行時に「部品目録と組み立て時の写しの一致」を folio parts --check が数える。build の依存 yaml-rust2 は既に在る（外部 crate は増えない）。名を型の名にする関数 variant は英小文字・数字・「-」だけを受ける = M0・M1 を受けない。
7. 改訂の範囲の下限（adr.rs の床の木の anchor.scope_minimum = schema・precedence・articles）は、憲法の schema.amendment_scope が **これを含むこと** を床が数える（link.rs の関数 amendment_range）。値は A-2.2 の字面（条文・schema 節・前文）の執行の形で、判断の記録の欄の決まりの生成区間に既に出ている。

## 3. 決めたこと

1. **憲法の値域 10 本は組み立て時に導出する。** build.rs が design-intent/constitution.yaml の schema.enums を読み、値域 1 本につき型 1 つ（閉じた一覧・ALL・名の列・name・from_name）を OUT_DIR へ書く。10 本のどれかが無い・一覧でない・空・重複・型の名にならない、は組み立ての失敗（黙って空にしない）。関数 variant は英大文字も受ける（M0・M1）。
2. **改訂の範囲の下限（A10）は写しではない。動かさない。** これは「憲法の file が自分の改訂の範囲を狭められない」ことを保つ下限で、file の側から緩められてはならない決まりそのもの（A-2 の門の番）。憲法の file から導出すると、file が articles を範囲から外した瞬間に下限も一緒に下がり、検査が空になる。ADR-11 (3) の「憲法自身の欄の決まりの節は (ア)」は値域の一覧の話で、門の番をする下限は (オ) の形 = 裁定の正本は憲法 A-2.2 の字面・執行する定数は実装・写しは生成区間に既に在る（P-5.6 を満たす）。
3. **対話面の行 id（A11）は写しではない。動かさない。** 規則の表の行を id で指しているだけで（P-5.2）、値の二重の記述ではない。
4. **今ある 2 つの突き合わせは、意味を変えて残す。** 床の撤退条件の種類（A9）と面の段（A16）は、導出の後は「この folio を組み立てた版の憲法」と「いま読んでいる置き場の憲法」のずれを落とす検査になる（部品目録の「組み立て時の写しの一致」と同じ役）。どちらの側も人が 2 度書いてはいないので P-6.4 の形ではない。文言と種別と凍結の歯は変えない。便 50 で面の側を「値域の節に在る鍵だけ、組み立て時の写しと長さ・字面・順を比べる」に広げる（fixture は在る鍵しか持たないので直さずに済む）。床の側は広げない（§1 の 5）。
5. **つなぎの集合の一致は入れない。**（§0 の 3）
6. **規則の表の欄の決まりの節は (イ)。** 門が無いので、実装の型付きの定数（床の木）が正本で、rules.yaml の schema の節を生成区間に替え、命令 folio schema の 4 本目の対象にする。値は変えない（状態の順は今の file の順 = 仮・凍結・未定 を床の木の順にする）。stage は憲法から導出した名の列を使い、kind_map_to_constitution の右辺も導出した型の名を使う = 憲法の値と規則の表の値が 1 か所から出る。床は schema.top_level を file からではなく定数から読む（file の側で節を足して通す口を塞ぐ・N-3.1）。行の required の全欄を床が数えるかどうかは別の話（今は id・article・what だけ）で、本便では締めない。
7. **退役待ちの render.rs の 10 枚は触らない。** 読み物の退役（器の側 s2-07l.467 の後）で file ごと無くなる。

## 5. 帰結と注意

1. **憲法の値域を改訂する版の手順が 2 手増える。** A-2 の手順の「folio inject --write」の前に、組み立て直し（cargo build）と folio schema --write（判断の記録の欄の決まりの生成区間の撤退条件の種類が変わるとき）。凍結した土台 tests/fixtures/floor_base/ の憲法は値域の古い版のままなので、その版では retreat_kind を変えるなら土台へ最小の patch が要る（土台の README の決まりのとおり）。
2. **古い folio で新しい憲法を読むと**、撤退条件の種類と（便 50 の後は）面に出る値域の全部で、ずれが違反か Err として出る。床しか回さないと retreat_kind 以外のずれは出ない = 残る穴。CI は毎回組み立てるので main では起きない。
3. **組み立てが憲法の file に依る。** 憲法が読めない置き場では folio を組み立てられない（部品目録と同じ・repo の外からの組み立ては今も出来ない）。
4. **床の穴（§0 の 5）** は便 49〜51 では塞がない。塞ぐ便は導出した型の from_name をそのまま使える（便 49 の後）。

## 6. 撤退条件

便 49 か便 50 が、同じ理由で R-7 の回数を超えて戻る・または導出した型が面の生成器の出力の byte を変えずに入らないと分かったら、案 3（面の側だけ実行時に読む・床の 2 本は便 49 のまま）へ切り替える。切り替えは本ノートの改訂で残す。
