## 持ち主へ問う項（B・変更前 → 変更後）

### 1. 憲法 P-3 の平易文（21 周目 忠実さ F-2・23 周目 忠実さ F-2）

- 前 — 機械が数えられること（部品が揃っているか等）は機械の側に、意味（分かりやすいか等）は AI の側に置きます。
- 後 — 機械が何度やっても同じ結果になる形で数えられること（部品が揃っているか等）は機械の側に、意味（読みやすいか・元の文に忠実か）は AI の側に置きます。

規範文 P-3.1 の条件「決定的に」（語彙の言い換え = 何度やっても同じ結果になる形で）と、規範文 P-3.2 が名指す 2 つ（読みやすさ・忠実さ）が平易文に戻る。条 P-5 と P-14 の平易文は同じ言い換えを既に置いている。条の id・見出し・規範文・段・縛る相手は 1 字も変えていないので A-2.2 の改訂には当たらない。

### 2. 憲法 P-15 の平易文（23 周目 読みやすさ F-7）

- 前 — 後から確かめる検査も、その判定を同じ 1 つの関数で見ます（同じ中身を別々に 2 か所へ書いたのでは足りません）。
- 後 — 後から確かめる検査も、その判定をプログラムの同じ 1 か所で見ます（同じ中身を別々に 2 か所へ書いたのでは足りません）。

「関数」は作り手側の語で用語集から引けない。規範文 P-15.2 の義務（同じ関数で確かめる）は変わらない。

### 3. 憲法の機構の「いつから動くか」（live）12 本（23 周目 実態 F-1・F-2）

- 前 — P-1・P-3・P-4・P-10・P-12・P-13・N-1・N-5 = M0 ／ P-7・P-11・P-17・P-18 = delivery-0（便 0 で実在する）
- 後 — P-1・P-3・P-4・P-10・P-12・N-1・N-5・P-7 = now ／ P-11・P-13・P-17・P-18 = M1

7 本（P-1・P-3・P-4・P-10・P-12・N-1・N-5）は機構がもう実装に在る（例えば承認欄の欄充足は folio check が数え、実の正本で 合格 が出る）のに M0 のままだった。P-7 も、憲法の写しの列と、便 88（2026-09-22 着地）が足した要件・判断・受入基準の id の一覧の 2 つで baseline を持つので now にする（機構の注は便 88 の字をそのまま使う）。逆に P-11・P-17・P-18 は、便 0 が 2026-09-17 に着地したので「もう在る」と読めるのに、極性一覧を出す口も rules 行の差分の裁定 id を数える口も実装に無いので M1 にする。P-13 は起草の時点で now にしていたが、前の版の置き場への書き込み口の回帰を落とす検査が 1 本も無いので M1 に戻した（独立の検証役の指摘・now にすると検査が無いのに確定値を出す条になる）。残る一部の不足は、どの条も機構の注が「まだ分からない」と書く形（条 P-2・P-5 と同じ形）に揃えてある。実装は 1 行も変えない。機構の欄は A-2.2 の改訂の範囲の外である。

**この項は断りを 1 つ含む。** 憲法の schema の「いま動く（now）」の意味は「**発効（2026-09-12）の時点で**、不合格を出せる検査が実在する」である。今回 now にする 8 本の検査は Rust の実装が入った 2026-09-17 以降のものなので、字義どおりには合わない。この欄を「今は在る」の意味で読み替えて直している。schema 節の字は改訂の母集合の中なので本一括では動かせず、揃えるには憲法改訂（判断の記録と承認）が要る＝次の周で同じ所見が出る見込みがある。
