## 2. 🔴 持ち主へ問う項（2 問・問 2 を先に）

### 🔴 問 2: v3 の合流先の repo は、新しい repo（scribe3）か、folio2 の repo を v3 に育てるか

- **やりたいこと**: v3 の合流先の repo を、今 v3 の設計の置き場が在る新しい repo（`scribe3`・private・folio の実装は後から取り込む）と決める。folio2 の repo は、合流までは folio の実装と folio2 の設計文書の置き場のまま残る。
- **理由**:
  - あなたは scribe2 の側で「それをfolio2で作ってはだめなのか？」と問うた（s2-07l.214 notes・2026-09-24T08:40Z）。この問いへの答えは、scribe2 席の連絡にも、v3 の起こしの文書（scribe3 の `docs/handoff/2026-09-24-v3-kickoff.md`）にも、台帳にも見つからなかった。
  - 答えで ADR-21 の前提が変わる。新しい repo なら、合流の前の v3 の置き場は folio2 と別の repo・別の憲法の名・本流の 1 つの組み立てで検査される置き場になり、条 P-13.4 の「外部の利用者で受入が通った後に self-host を始める」の順がそのまま成り立つ（合流の前の v3 で受入 → 合流 → v3 が自分の便で自分を運ぶ）。
  - folio2 の repo を v3 に育てるなら、v3 の置き場は最初から folio の実装と同じ repo に在り、外部の利用者と数えられない。そのとき ADR-21 は発効の直後にやめる条件 (1) に当たるので、発効させず保留（案 c）に倒す方が、判断の記録 1 本の往復を無駄にしない。
  - 新しい repo の置き場は既に在る（`5091abb`・その後に討論の起こしと論点 D の討論の commit）。
- **代替案**: folio2 の repo を v3 に育てる。folio の実装と v3 の設計が最初から同じ repo に入り、合流の手間は減る。代わりに、M3 の「外部の利用者」は v3 では立たず、P-13.4 の物差しを別に立てる判断（新しい M3 の判断の記録・案 b の形）が要る。scribe3 の置き場の中身は folio2 の repo へ移すことになる。
- **コスト**: この答えは 1 語で済む。新しい repo なら、問 1 へ進む。folio2 の repo なら、問 1 は案 c（保留）になり、M3 の物差しを立て直す判断の記録を後で起こす。
- **推奨**: 新しい repo（scribe3）。置き場は既に在り、ADR-21 の限定と P-13.4 の順がそのまま成り立つ。

- **「まだ決めない」と答えたとき**: v3 の合流の形は v3 の討論の論点 A（scribe3 の起こしの文書 §2）で決めることになっている。「まだ決めない（v3 の論点 A で決める）」の答えなら、問 1 は案 c（保留）として扱い、発効させない。論点 A の答えが v3 の席から着いたときに、問 1 を改めて問う。

回答の例: 「問 2 は推奨で（scribe3）」「v3 は folio2 の repo で作る」「まだ決めない（v3 の論点 A で決める）」。

### 🔴 問 1: 判断の記録 ADR-21 を発効してよいか（問 2 が「scribe3」のとき）
