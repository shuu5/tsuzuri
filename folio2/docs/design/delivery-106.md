## 1. 設計

### (a) いま起きていること（実測・数え方は (i)・参考値は base main 06e83d7 での測り）

`crates/folio/src/schema.rs` は 2 つの役を同居させている。

1. **命令 `folio schema` の口**（対象 9 file の表・生成区間を取る口・`--write` と `--check` の本体・終了コード）。責務の層は **3 導出する**。
2. **床の機械**（欄の決まりの床の定数が持つ木の型 `Floor`・欄の集合を木に写すマクロ `keys_floor`・注釈の欄を落とす `strip_notes`・正本の木と突き合わせる `floor_diff`・木を生成区間の本文へ導出する `derive` と、その字面を組む非公開の補助 6 本と幅の定数）。責務の層は **1 読む**（正本の形だけを知り、何も書かない）。

2 の側を、床の検査の 7 file（判断の記録・設計ノート・天井の正本・入口の正本・規則の表・正本 7 file の床・相談窓口）が名指している。7 file はどれも層 **2 検査する** なので、この 7 本は **層が上がる辺**（下から上を名指す＝ADR-15 決定 (2) の向きの決まりに反する）である。設計ノート §3-a の 20 本のうち 7 本がこれで、出どころは同居そのものである（§3-b の 1 番）。

余地の側でも同じ file が効いている。`adr.rs` の余地は **110**、`note.rs` は **138**（どちらも参考値）で、この 2 本を書き換える中くらい（size M・見積 300）の便は受付で断られる。本便はその 2 本を名指しの 1〜2 行だけ触るので size S に収まるが、**塞がりそのものを開けるのは ADR-15 の列の後半（便 113・便 114）である**。本便が運ぶのは向きの直しだけで、余地の塞がりは開けない。

### (b) 直す先 — 床の機械を新しい `floor.rs`（層 1 読む）へ字を変えずに降ろす

`schema.rs` の 2 つの区間（幅の定数の 2 行と、注釈 床の機械 から `derive` の閉じ括弧までの 239 行・参考値）を、新しい file `crates/folio/src/floor.rs` へ **1 字も変えずに** 移す。移す項目は次のとおり。

| 移すもの | 役 | 見え方 |
| --- | --- | --- |
| 幅の定数 | 1 行の幅の上限（100 字） | 非公開のまま |
| `Floor` | 床の定数の木の型（値・数・値の一覧・木の一覧・表の 5 つ） | 道具の中で公開のまま |
| `keys_floor` | 欄の集合（必須と任意）を床の木の表に写すマクロ | 道具の中で公開のまま |
| `strip_notes` | 名が `_note` で終わる欄を入れ子ごと落とす | 道具の中で公開のまま |
| `floor_diff` | 正本の木と床の木を字面で突き合わせて違いを並べる | 道具の中で公開のまま |
| `derive` | 床の木から生成区間の本文を組む（決定的） | 公開のまま |
| 字面を組む補助 6 本 | 引用符の要否・flow の 1 行・表が平たいか・幅に収まるか・block の表・block の項 | 非公開のまま |

**見え方（私か、道具の中で公開か）は 1 か所も広げない。** 移した 7 項目はどれも移す前と同じ印を持ち、非公開の補助 6 本と幅の定数は新しい file の中だけで使われるので非公開のまま閉じる。起草役は写しの repo で、削除した行と追加した行の 道具の中で公開 の印の数が同数であることと、`floor.rs` と `schema.rs` の空でない行のうち base の `schema.rs` に同じ字で無いものが **13 行**（新しい file の頭の注 6 行・`schema.rs` の頭の注 3 行・マクロの中の道 3 行・`schema.rs` の取り込み 1 行）しか無いこと（参考値）を、全数の突き合わせで確かめた。設計ノート §4-d が挙げる 見え方を広げた箇所 の累計 183 のうち、**本便の分は 0** である。

`schema.rs` に残るのは命令の口だけ（対象 9 file の表・生成区間を取る口・実行の様態の型・1 回の実行の結果の型・file 1 本の処理・全体の口）で、新しい file から `Floor` と `derive` を取り込む。

**名指しの行だけを書き換える 8 file**（`adr`・`note`・`ceiling`・`entrance`・`rules`・`check`・`intake`・`graph`）は、取り込みの 1 行と、床の木を生成区間の字面に直して凍結の写しと比べる単体の歯の 1 行だけが変わる（合計 13 行）。`main.rs` は区切りの宣言を 1 行足す。**この 9 file では、ほかの行は 1 字も動かない。**

マクロ `keys_floor` は展開の先で床の木の型を絶対の道で名指すので、その道を 3 行だけ新しい区切りの名へ書き換える（設計ノート §4-b の マクロの中の道も書き換える）。

**順を逆にできない理由**（ADR-15 の退けた案 e）: 床の定数そのものを先に降ろす便（便 113・便 114）を先に運ぶと、降ろした先が床の木の型を層をまたいで名指すので、層が上がる辺は入れ替わるだけで減らない。型を先に降ろすと、あとの便は層 1 の中で閉じる。だから型が先である。

### (c) 採らなかった形

| 形 | 退けた理由 |
| --- | --- |
| 床の機械を `schema.rs` に置いたまま、床の検査の側から名指す道だけを付け替える | 名指す先が同じ file のままなので、層が上がる辺は 1 本も減らない。ADR-15 決定 (3) は同居を解くことを求めている |
| 床の機械を層 0（土台）へ置く | 床の木の型は正本の形（欄の名と値域）を知っているので、層 0 の定義（文書を何も知らない）に当てはまらない。設計ノート §1 の層 1 の定義（正本の byte を型に直す・閉じた一覧・値域・床の木の型を持つ）が当たる |
| 床の機械を 2 つに割る（型と導出を別の file に） | 導出の補助 6 本は型の中身に強く依存し、1 つの単体の歯が両方を測っている。割ると歯を書き換えることになり、振る舞い不変の主張が弱くなる。file 数を増やす利もない |
| 境界の歯を実装の側（`src/`）に置く | 実装が自分で自分を採点する形になる（条 P-10.2）。ADR-15 決定 (4) は歯の側に置くと定めた |
| 境界の歯の一覧に、無効化の旗や 今回だけ の口を置く | 条 N-3.1 が拒む。歯 2 は集合の一致を見るので、辺を足しても減らしても落ちる |

### (d) 歯の土台

本便は新しい凍結の土台（fixture）を作らない。使うのは既に在る 3 つである。

- `crates/folio/tests/schema.rs`（18 本）: 実の正本の生成区間と**凍結した要約値**の一致・区間の 1 byte のずれで落ちること・印が無い／2 つある／逆順のときに まだ分からない になること・`--write` が区間だけを直し何度撃っても同じになること。
- `crates/folio/tests/schema_docs.rs`（27 本）: 天井の正本・規則の表・入口の正本・要件書・語彙・相談窓口の 6 file について、生成区間と**凍結した anchor** の一致と、1 byte のずれで落ちること。
- `crates/folio/tests/floor_cases.rs`（11 本・うち 1 本が **134 場合**の床の表を回す）: 床の検査が場合ごとに期待の 3 値と期待の字を返すこと。床の機械（突き合わせと注釈の欄の落とし）が変われば、この 134 場合のどれかが必ず落ちる。

境界の歯（(e) の 2 本）の土台は、実装の側の file そのもの（`crates/folio/src/*.rs` と入口の宣言）である。**これは条 P-10.1 が求める独立した凍結 anchor ではない**（同じ便・同じ書き手が同じ書き込み範囲の中で書き直す）。ADR-15 はこれを 凍結した実測 と位置づけ、独立性の主張を取り下げている。本便もその位置づけのまま運ぶ（言えないことは (h) に書く）。

### (e) 歯（新しく 2 本・既に在る歯は 1 本も落とさない）

新しい file `crates/folio/tests/modules.rs` に、ADR-15 決定 (4) の境界の歯を 2 本置く。この file は層の割り当ての表（45 行）と、まだ降ろしていない層が上がる辺の一覧（13 対）を型付きデータで持つ。

| 歯 | 何を数えるか | 落ちるとき（起草役が実測で確かめた） |
| --- | --- | --- |
| `p106_layers_cover_every_module` | 層の割り当ての表の区切りの集合が、入口 `main.rs` の区切りの宣言の集合と**ちょうど一致**する（さらに `src/` の file 名の集合とも一致する） | 表から 1 行落として撃つと 落ちた（層が無い: floor と出る） |
| `p106_edges_point_down` | 注釈と字面を剥がした `src/*.rs` を走査して辺を集め、層が上がる対の集合が凍結した一覧と**ちょうど一致**する | `adr.rs` に層が上がる名指しを 1 本足して撃つと 落ちた（一覧に無い: adr と schema の対 と出る） |

歯 2 は集合の一致を見るので、**辺を足しても減らしても落ちる**。無効化の旗も 今回だけ の口も持たない（N-3.1）。走査の式は設計ノートの冒頭のとおりで、注釈（`//` と `/* */`）と字面（文字列・素の文字列・1 文字）を剥がしてから、絶対の道と括り書きを解いて相異なる名を取り、入口 `main.rs` だけは接頭辞の無い名も数える。

**既に在る歯は 1 本も名を変えず、1 本も消えない。** ただし `schema.rs` の中の単体の歯 4 本のうち **3 本**（床の木の突き合わせ・引用符の規則・幅での flow と block の切り替え）は、測る先が新しい file へ降りるので、**同じ file へ本文を 1 字も変えずに移す**（残る 1 本は生成区間の印を測るので `schema.rs` に残る）。名は 1 つも変えない。この 3 本は非公開の補助を測るので、元の file に残すと届かない。ADR-15 決定 (5) の 既存の歯は 1 本も動かさない は本文と名を変えないことと読み、3 本の置き場だけを移す。残すと非公開の補助 6 本の見え方を広げることになり、決定 (3) が契約に書けと言う見え方の拡大が 0 でなくなるためである。**歯の本数は base の 777 本 + 境界の歯 2 本 = 779 本**（参考値）である。

### (f) 凍結 anchor が動かないこと・出力が動かないこと

本便は `design-intent/` の下も `crates/folio/tests/fixtures/` の下も **1 byte も触らない**。主張は次の 4 つで、どれも既に在る歯か本便の verify が数える。

3. **憲法の生成区間が動かない。** `folio inject --check` が 一致・終了コード 0。

**この便の歯が言えないこと**（設計ノート §5-a の 6 つのうち、本便に当たる 4 つ）。

1. 境界の歯は**独立した凍結 anchor ではない**。層の割り当ても辺の一覧も、実装と同じ便・同じ書き手が同じ書き込み範囲の中で書き直せる。
2. 走査は**字面だけを見る**。再輸出を挟めば、辺を一覧に書かずに同じ依存を作れる（今の repo に先例が 2 つ在る: 面の生成器の file の丸ごとの再輸出と、部品目録の定数の別名での再輸出）。**本便は再輸出を 1 行も置かない**が、後続の便が置く見込みである。
3. 走査は**区間の外から接頭辞なしで取り込んだ名を見ない**。本便はこの穴を組み立てで塞いだ（写しの repo で `cargo build` を警告 0 で通し、幅の定数を一緒に移す必要があることを実測で見つけた）。
4. 歯の file は**辺を動かす便すべての合流点**になるので、便 107 以降と並行に運べない（直列になる）。

**撤退条件**。ADR-15 の撤退条件 (2) を本便に当てると、着地後の層が上がる辺が直前（base の 20 本）より**増えていたら**、決定 (5) の順を組み直す。増えたかを捉えるのは、境界の歯の file の差分（凍結した一覧の行の増減）を読む取り込みの審査であり、記帳は台帳 f2-648 に行う。歯は一覧との一致しか見ない。本便の計画値は 13 本（参考値）で、13 本と違ったら（20 本以下でも）計画か実測のどちらかが誤っているので、次の便を出す前に審査が列を見直す。これは ADR より厳しい本便の自主の条件である。どちらの場合も区間の切り出しは戻さない。戻すと 7 本の層が上がる辺が復活し、列の残り 10 本の前提が全部崩れるためである。

### (i) 数え直す手順（誰でも撃ち直せる形・規則の表の行 D-13）

本便の契約が挙げる数は全部 **参考値**で、正本は実測である。組み直す手順は設計ノート `docs/design/module-map-2026-09-23.md` の §7 と同じで、次の 4 つである。

1. **正規化行と余地**: 空行を含む全行を数え、1 行の字数（Unicode の字の数）が 120 を超える行は 切り上げ(字数 ÷ 120) − 1 だけ足す。余地 = 1,500 − その値。
2. **辺と層の向き**: 設計ノートの冒頭の走査の式（注釈と字面を剥がし、絶対の道と括り書きを解き、入口だけ接頭辞なしも数え、自分自身は数えない）を当て、設計ノート §2 の層の割り当てで 下向き / 同じ層 / 上向き に分ける。**本便の後は境界の歯そのものがこの式を持つ**ので、`cargo nextest run -p folio --test modules` が数え直しである。
3. **生成区間の byte**: `folio schema --dir design-intent --check`。
4. **便の diff の大きさ**: base の commit と便の commit の差を byte で測る。
