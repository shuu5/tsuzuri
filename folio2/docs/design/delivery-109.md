## 1. 設計

### (a) いま起きていること（実測・数え方は (i)・参考値は base での測り）

2 つの file が、面の生成と閉じた一覧を同居させている。

1. `crates/folio/src/face_labels.rs`（層 4 面に出す）は、面の共有の名札（憲法の値域の型への網羅の場合分けと、値域に依らない名札の表）と、**入口の棚の閉じた一覧**を持つ。棚の一覧は、棚の文書の型 `Shelf` と、文書の id から棚への表 `SHELF_DOCS`・関係の id から置き場の class への表 `SHELF_RELATIONS`・付録の id から章の番号と数の単位への表 `ANNEXES`・凡例の id から sw の class への表 `SHELF_LEGEND` の 5 つである（71 行）。どれも入口の正本の棚の行に許す id の集合を閉じる。
2. `crates/folio/src/face_note.rs`（層 4）は、設計ノートの面の生成と、**設計ノートの状態の閉じた一覧** `STATUS`（状態の値から名札への表）と、**文書 id の形** `is_doc_id`（欄の決まりの id_pattern を手書きで判じる関数）を持つ（13 行）。

1 の一覧は `face.rs` が `face_labels.rs` を丸ごと再輸出するので、呼ぶ側は `face` の名で名指している。**入口の正本の検査 `entrance.rs`（層 2 検査する）が、棚の閉じた id の列を組み立て時に取り出すために `face` を名指す**。これが便 108 の後に残る 層が上がる辺 7 本のうちの 1 本（`entrance` → `face`）で、実際の行き先は再輸出の元の `face_labels.rs` である（設計ノート §5-a の 4 の先例そのもの）。入口の面の生成器 `face_index.rs` と面の入口 `face.rs` も同じ一覧を読む。

2 の一覧は、入口の面の生成器（設計ノートの行の状態の名札と id の形）と図の命令 `figure.rs`（--doc の id の形）が `face_note.rs` を名指して読む。どれも同じ層 4 の辺で決まりには反していない。ADR-15 の決定 (2) が名指すのは部品目録と入口の棚の閉じた一覧だけで、この 2 つは材料の設計ノート §4-b の便 109 の行が棚の一覧と 1 便で運ぶと定めたものである。状態の表の鍵と id の形は、設計ノートの床（`note.rs`）が持つ状態の閉じた一覧と id の形の手書きの 2 つ目でもある。本便はこの重なりを広げも狭めもしない。

区間の外に定義がある名の列挙（ADR-15 決定 (5)）: 棚の一覧が使う名は同じ区間の `Shelf` だけで、状態の表と id の形は区切りの名を 1 つも使わない。区間を切り出して組み立て（`cargo build --all-targets`）を 0 警告で通して確かめた。

便 108 の後の 層が上がる辺は **7 本**（参考値）。境界の歯の file の凍結した一覧と一致している。

### (b) 直す先 — 2 つの閉じた一覧を新しい `shelf.rs`（層 1 読む）へ、字を変えずに移す

**1. 棚の閉じた一覧**（`face_labels.rs` の 71 行・型 1 と表 4）と、**設計ノートの状態の閉じた一覧と文書 id の形**（`face_note.rs` の 13 行）を、新しい file `crates/folio/src/shelf.rs` へ字を変えずに移す。新しい file の頭の注 3 行は、何をどこから降ろしたかと誰が読むかを書く。`face_labels.rs` と `face_note.rs` は頭の注を 1 行ずつ足す。`face_labels.rs` に残る名札の表（文書の状態・確かめ方・図の色・入口の状態の 4 つ）と、`face_note.rs` の面の生成の本体は 1 字も動かない。

**見え方の拡大は 0 か所**（ADR-15 決定 (3) が契約に書けと言う数）。棚の一覧はいま公開の印を持ち、`face.rs` の丸ごとの再輸出を通して道具の中のどこからでも届く。新しい file は入口の私の区切りなので、公開の印のままで届く範囲は同じである。状態の表と id の形は道具の中で公開の印のまま移る。起草役は src 全体で、道具の中で公開の印が 123 → 123、公開の印が 367 → 367、再輸出の行が 3 → 3 であることを数えた（参考値）。**再輸出の行は 1 行も置かない**（便 106〜108 と同じ）。`face.rs` の `face_labels.rs` の丸ごとの再輸出は残るが、そこから棚の一覧が抜けるだけで行は動かない。

**名指しの行だけを書き換える file**。棚の一覧を `face` 経由で、状態の表と id の形を `face_note` 経由で名指していた file は、どれも新しい file を直接名指すように取り込みの行を書き換える。

**撤退条件**。ADR-15 の撤退条件 (2) を本便に当てると、着地後の 層が上がる辺が直前（便 108 の着地後の 7 本）より**増えていたら**、決定 (5) の順を組み直す。増えたかを捉えるのは、境界の歯の file の差分（凍結した一覧の行の増減）を読む取り込みの審査であり、記帳は台帳 f2-648 に行う。歯は一覧との一致しか見ない。本便の計画値は 6 本（参考値）で、6 本と違ったら（7 本以下でも）計画か実測のどちらかが誤っているので、次の便を出す前に審査が列を見直す。これは ADR より厳しい本便の自主の条件である。どちらの場合も区間の切り出しは戻さない。戻すと 1 本の層が上がる辺が復活し、列の残りの前提が崩れるためである。

構造の歯の直しについての撤退条件は ADR-15 に無い。本便は自主の条件として、取り込みの審査が構造の歯の差分を (e) の 2 の範囲の外（3 本の頭のほかの見張りの変更・名の変更・見張りの数の減り）と判じたら、差分を差し戻して契約を改訂する。棚の一覧は層 2 の読み手（入口の正本の検査）を持ち、層 1 の定義に当たる。設計ノートの状態の表は、鍵が正本の値域で、値が面に出す名札である。どちらの層にも属する部分に当たりうるので、ADR-15 の撤退条件 (3) の数えに入れるかは取り込みの審査が判じる（撤退条件 (3) の判定者）。

### (i) 数え直す手順（誰でも撃ち直せる形・規則の表の行 D-13）

本便の契約が挙げる数は全部 **参考値**で、正本は実測である。組み直す手順は設計ノート `docs/design/module-map-2026-09-23.md` の §7 と同じで、次の 6 つである。起草役の台本（区間を当てる 1 本・走査・行数・変異・出力の比較）と実測 patch は `~/.local/share/folio2/handoff-2026-09-23/` の起草の記録 `d109-draft.md` が場所と撃ち方を持つ。

1. **正規化行と余地**: 空行を含む全行を数え、1 行の字数（Unicode の字の数）が 120 を超える行は 切り上げ(字数 ÷ 120) − 1 だけ足す。余地 = 1,500 − その値。
2. **辺と層の向き**: 設計ノートの冒頭の走査の式に字面の剥がしを足したもの（注釈と字面を剥がし、絶対の道と括り書きを解き、入口だけ接頭辞なしも数え、自分自身は数えない）を当て、層の割り当てで 下向き / 同じ層 / 上向き に分ける。境界の歯そのものがこの式を持つので、`cargo nextest run -p folio --test modules` が数え直しである。起草役の独立の走査では、base が 47 file・233 辺（下 154・同じ層 72・上 7）、本便の後が 48 file・235 辺（下 159・同じ層 70・上 6）だった（参考値）。消える辺は 3（入口の正本の検査から面・入口の面から設計ノートの面・図から設計ノートの面）、足す辺は 5（入口の正本の検査・面の入口・入口の面・設計ノートの面・図から新しい file・どれも下向き）。
3. **区間の純度と見え方と歯の名**: base と本便の後の diff の足した行と消した行を多重集合で照らす（移動は 88 行。移動でない行は (g) の新しく書く行と、取り込みと区切り名の旧い行だけ）。構造の歯の file の差分で移動でない行は、足す側が頭の注 1 行・2 つの表の注 2 行・降りた 3 本の表の開き 1 行・3 本を見張る輪の 15 行の 19 行、消す側が元の表の注 1 行だけである（3 本の頭の字面と表の閉じと空行は多重集合の上で移動と数える）。見え方は src 全体の 道具の中で公開 の印と 公開 の印と再輸出の行の数を base と比べる。歯の名は `cargo nextest list --workspace` を base と並べ、sort して比べる（違いは 0）。
4. **出力の byte**: base と本便の後の binary で `folio build --write`・`folio ceiling --write`・`folio intake --print`・`folio graph --print`・`folio parts --print`・`folio parts --check`（組み立ての出力の 5 面）を撃ち、`diff -r` と `cmp` で比べる。
5. **生成区間の byte**: `folio schema --dir design-intent --check`。
6. **便の diff の大きさ**: base の commit と便の commit の差を byte で測る。
