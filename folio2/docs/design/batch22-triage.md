### 判定 1 ＝ 制約 CON8 の前の文は ADR-16 決定 (1)(5)、後の文は ADR-16 決定 (5)(7) を出所にする

- **所見の指摘は正しい。** 前の文は「契約表を設計ノートの YAML 正本の節に置き、器が読む導出物をそこから作る形は、M3 の出口の利用者…が自分の repo で最初からその形で書く契約表に当てる」と言う。当てる相手を決めるのは ADR-16 決定 (1)（M3 の範囲＝契約表を持つ設計ノートを外部の利用者が置き場に置き、器が読む導出物をそこから作れる）で、ADR-21 決定 (1) がその利用者を v3 の設計の置き場と読み替えた。ADR-16 決定 (7) は便の列と順序で、当てる相手を決めていない。
- **前の文の括弧は ADR-22 決定 (2) と同じ (1)(5) にした。** ADR-22 決定 (2) の逐語は「その向きを M3 の出口の利用者（v3 の設計の置き場）が自分の repo で最初から設計ノートの形で書く契約表に当てるのは、ADR-16 決定 (1)(5) と ADR-21 決定 (1) である」。ADR-16 決定 (5) は導出物の形と、器の受付がその導出物を読んで通すこと（判定点 ③）を定め、前の文の「器が読む導出物をそこから作る形」に当たる。
- **後の文の括弧に ADR-16 決定 (5)(7) を足した。** ADR-22 決定 (1) の逐語は「導出物の口の段は、ADR-16 決定 (5)(7) と要件 FR11 の段の欄（M3）が持つ」。後の文「導出物を作る口は M3 の口として作った」の「M3 の口として」の出所がこれに当たる。一括 21 で 1 文を 2 文に割ったとき、(5)(7) は後の文の出所なのに前の文に残った（所見の読み）。
- **台帳の控えの字「決定 (1) だけ」とは違う形である。** 台帳 f2-648.215 の description は「括弧を判断の記録 ADR-16 決定 (1)・ADR-21 決定 (1) に直す」と書き、根拠に「ADR-22 決定 (2) もそう書く」を挙げる。ADR-22 決定 (2) の実物は「(1)(5)」で、所見 F-1 の勧めも一括 21 の仕分けの承認の後の欄 #13 も「前の文は (1)(5)・後の文は (5)(7)」だった。「(1)」だけにすると、ADR-22 決定 (2) と制約の本文が別の出所を言う形になり、次の周の整合が同じ所を拾う見込みがある。そこで所見と #13 の形を推奨にし、台帳の字の形を代替案 A に置いた（問 1）。どちらも同じ引き金の欄の中の直しで、周の数は変わらない。
