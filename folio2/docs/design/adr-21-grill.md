## 1. 改訂が主張する利益と、失うもの

- 主張する利益: ADR-16 の出口が再び届く相手を持つ（scribe2 は移行を取りやめたので、字のままでは出口の日が来ない）。scribe2 が閉じてよいと言った 3 つの論点（9 形の参照 id・章の上限 12 を超える文書・器の暫定の散文の門の撤去）が、判断の記録の上で閉じる。ADR-16 の便 ①〜⑤ の着地（FR11・FR22〜FR25）は無駄にならず、v3 の入口としてそのまま使える。
- 主張しない利益: v3 の入口の便の順・v3 の設計の形・合流の時機。どれも本判断の外である。
- 失うもの（と疑われるもの）: 「外部の利用者」の性質が v3 では時限付きになる。判定点 ②③ の相手（導出物の file を読む器）が v3 で消えるかもしれない。scribe2 の側の値のために用意した「参照 id の形を置き場ごとに選ぶ」向きが、便を持たない字だけの向きになる。

## 3. 反証の試みと応答

### ① 出口の日が本当に来ないのか（読み替えは要るか）— 支持

- ADR-16 決定 (1) の出口は「利用者（scribe2）の 1 本目の設計ノートが判定点 ①〜③ を通ったとき」。scribe2 の持ち主の裁定は scribe2 の設計文書を folio2 の形へ移す段を取りやめたので、scribe2 の 1 本目は置かれない。
- 崩しの試み: 「scribe2 の repo に新しく書いた設計ノートを 1 本置けば出口に届く」。連絡は scribe2 が残りの契約を前の版の道具で畳むと言っており、新しい設計ノートを folio2 の形で書く予定は無い。案 e（scribe2 のまま待つ）は待つ相手の予定が無い。再開したら撤退条件 (4) で戻す。
- 結論: 読み替えは要る。

### ② v3 の置き場は「外部の利用者」か（条 P-13.4）— 条件付き支持（決定 (1) の末尾と撤退条件 (1) に書いた）

- ADR-16 は M3 を P-13.4 の「外部の利用者の受入」の最初の段とした。v3 は folio2 を合流させる世代で、いずれ folio の実装を同じ repo に持つ。
- 崩しの試み: 合流の後の v3 は、folio の実装と検査される設計文書を同じ repo に持つ。ADR-16 案 a の理由は、列の根の表が道具の側に在るので「検査される側の data で根を選び直せない」とし、その守りは「組み立ての取得と固定が利用者の手の届かない形で決まったとき」に外側の証人になるとした。合流の後は、v3 の同じ repo の便が列の根の表と検査される憲法の両方を書けるので、この外側の証人の性質が消える。
- 応答: 合流の前の v3 の置き場は、別の repo・別の憲法の名・同じ 1 つの組み立て（本流の folio を撃つ）で、ADR-16 が数えた性質を持つ。だから「合流の前に限る」を決定 (1) に書き、合流が判定点 ①〜③ の記帳より先に来た回を撤退条件 (1) で 1 回で持ち主へ上げる。合流の時機は連絡に無く、まだ分からない。
- 残る危うさ: 連絡は「1 repo」がどの repo か（新しい repo か、scribe2 か folio2 の repo を育てるか）を書いていない。folio2 の repo を v3 に育てる形なら、v3 の置き場は最初から folio の実装と同じ repo に在り、外部の利用者と数えられない。そのときは撤退条件 (1) が本判断の発効の直後に当たる。
- （改訂 c: v3 の置き場は新しい repo `scribe3` に既に立っていた〔`5091abb`〕。一方で持ち主は scribe2 の側で「それをfolio2で作ってはだめなのか？」と問うており、答えは記録に無い。承認要求に 🔴 問 2 を立て、問 1 をその答えに依らせた。撤退条件 (1) に憲法の名の限定も足した。）

### ③ 判定点 ②③ を保つべきか（案 d）— 条件付き支持（撤退条件 (2) を置いた）

- 崩しの試み: 連絡は v3 の境界を「設計ノートの行 → 契約」の型 1 本と書いた。同じ組み立ての束の中なら、器は導出物の file を介さず型を直に受けうる。そうなると判定点 ②（導出物の着地と差分 0）と ③（器が導出物を読む）は相手を失う。
- 応答: 型で受けるかは v3 の設計がまだ決めていない。v3 の最初の便は今の器（scribe2 の組み立て）が運ぶ見込みが高く、今の器は導出物の file を読む。今 ②③ を外すと v3 の設計を先に決めることになる。
- （改訂 c: 起草の時点の「器の受け口 s2-07l.473 は再開済み・未着地」は誤りだった。.473 は契約 s2-07l.586 へ引き継いで閉じ、.586 は scribe2 本流 `0337cf1`〔07:40 JST〕に着地した。v3 の起こしの論点 A の推奨も「設計ノートの行 → 契約（toml）」である。②③ を保つ理由は強まった。）
- 型の境界が発効したら 1 回で ②③ を問い直す（撤退条件 (2)）。その前は ②③ を保つ。
- 追加で直した所: v3 では判定点 ③ で読む器が今の器から v3 の中の器へ替わりうるので、判定点 ③ の記帳に読んだ器の組み立て（器の repo と commit）を名指すことを決定 (1) に足した。判定点 ① で撃った folio の組み立てを名指すのと同じ理由（どの組み立てで確かめたかが合否の一部）である。

### ④ 改訂の欄の形に収まるか — 条件付き支持（注に向きの読みを書いた）

- 崩しの試み: 改訂の欄の向きは narrow と widen の 2 値だけで、「利用者の名を替える」は向きを持たない置き換えである。置き換えなら ADR-16 を退役させて後継が supersedes する形（案 b）が正しいのではないか。
- 応答: 欄の決まりは supersedes を「判断を丸ごと置き換える」形、revises を「発効した判断が生きたまま、その決定の範囲が別の判断で変わる」形に分ける。ADR-16 は決定 (2)(4)(5) と便 ①〜⑤ の着地が生きたままなので revises に当たる。決定 (1) の改訂は、範囲から「設計文書を移す」話が外れ、出口の記帳に読んだ器の名指しが足される＝出口と数える状態の集合が減るので、narrow と読める。向きが本当かは人が読む（`revises_note.kind`）。
- 案 b の費用: 生きている決定を 1 字も変えずに写した長い後継を書き、要件 FR11・FR22〜FR25 と受入基準 AC23〜AC25 の判断の記録の欄と注の全部を直すことになる。後継が発効するまで下書きを 1 手も置けない（`supersede_note`）。得るものは字の上のまとまりだけで、注の 1 段と改訂の欄で足りる。

### ⑤ scribe2 の論点は本当に閉じてよいか — 支持（ADR-3 決定 (7) の撤去の句も閉じた）

- 9 形の参照 id: v3 は最初から folio2 の参照 id の形で書く（連絡の (エ)）。folio2 の門は 1 字も緩まない。参照 id の形を行 R-16 から読む便は M3 の出口に要らず（ADR-16 決定 (6) の字）、撤去の前提という理由も消えたので起こさない。要件 FR12 の規範文の直しもその便と同じ版の予定だったので行わず、FR12 は 4 種のまま残る。
- 章の上限 12: ADR-16 決定 (5) で導出物を配信の組み立てから切り離した時点で、章の上限は M3 の判定点から外れていた（案 i の理由）。v3 は上限の中で書く。
- 器の暫定の散文の門の撤去: 崩しの試み = 「ADR-16 決定 (6) が定め直した撤去の条件を閉じると、ADR-3 決定 (7) の元の字『M1 が引き取ったら撤去する』が生き返る。M1 の引き取りは便 24（2026-09-18）で済んでいるので、器は今すぐ門を外せと読める」。これは起草の初稿の穴だった。器の門は scribe2 の設計文書を folio の床に掛けないまま残るので、外すと scribe2 の散文にしか無い規則を落とす層が消える（scribe2 の 1 周目のコメントの論点）。
- 応答: ADR-3 決定 (7) の撤去の句も改訂の欄（narrow）で folio2 の判断の記録から外し、撤去の時機を器の持ち主の扱いにした（決定 (3) の末尾・revises の ADR-3 の行）。散文の門の式と folio2 の門は変えない。

### ⑥ 撤退条件は数えられるか — 条件付き支持（(5) を置いた）

- (1) 合流: v3 の repo の統合先の履歴に folio の組み立ての単位の置き場が現れた最初の commit と、判定点 ③ の記帳の時刻を比べる。v3 の repo の場所がまだ分からないので、読めなければ「数えられない回」に入る。
- (2) 型の境界: v3 の設計文書の判断の記録か設計ノートの状態の欄で数える。v3 の置き場は folio の形なので、発効の欄は機械で読める。
- (3) 30 日: 閾値は推測である。根拠は、ADR-16 の便 ①〜⑤ が 2026-09-24 に揃い、M3 の口が使われないまま置かれる期間を区切ることだけで、v3 の着手の予定は連絡に無い。短すぎれば持ち主へ問う回が 1 回増えるだけで、戻し先は「待ち続けるか」を含むので害は小さい。
- （改訂 c: 起草の時点の (3)「v3 の置き場が 30 日立たない」は、置き場が発効の前に立っていたので決して数えない死んだ条件だった。「発効から 30 日のあいだに判定点 ① の記帳が無い」〔数える口 = 台帳 f2-648 notes〕に替えた。(5) には数える時機〔v3 の統合先に commit が入った後の最初の本流の周の前〕と、台帳が立つ前は数えないことを書いた。）
- (4) scribe2 の再開: scribe2 の台帳を folio2 の席が読んで写す。scribe2 の台帳は別の repo の帳簿で、読めなければ (5) に入る。
- (5) 数えられない回は行 R-7 の回数を超えたら まだ分からない に落とす（ADR-20 の撤退条件 (4) と同じ形）。

### ⑦ 要件書に触る必要は在るか — 在る（承認の後に席が書く）

- 段の欄（milestone）: FR11・FR22〜FR25・AC9・AC23〜AC25 は M3 のまま。変えない。
- M3 の範囲の節: ADR-16 決定 (1) だけを指しているので、読み替えた ADR-21 を指し先に足さないと、節から辿った読み手が「scribe2」の字を正と読む。足す。
- 受入基準 AC23〜AC25 の平易文と固定の材料: 「利用者（scribe2）」「scribe2 は s2- の項」「scribe2 が読む形」の字が在る。v3 の置き場の字にし、AC25 の判定の文に読んだ器の組み立てを足す（決定 (1)）。
- 要件 FR22 の注: scribe2 の置き場と骨格の宣言の形の字が在る。決定 (2) の限定を 1 文足す。
- 制約 CON8: 「契約表を持つ設計ノートを利用者（scribe2）の repo の folio の置き場へ置く段は M3」の字が在る。取りやめと読み替えを 1 文足す。
- 要件 FR11 の平易文の「scribe2 が読む形」: 今の器は scribe2 のままなので変えない（器が v3 の中へ替わったら直す）。
- 規範文と番号は 1 つも変えない（条 P-7）。要件書の版は 1 つ上がる。

### ⑧ 持ち主の判断を先回りしないか — 条件付き支持

- v3 の置き場の場所・憲法の名・台帳の接頭辞・境界の形・合流の時機は、どれも v3 の設計（v3 の持ち主）が決める。本判断は folio2 の側の読みだけを決め、v3 の側の選択肢を狭めない。
- 崩しの試み: 決定 (2) の「v3 の骨格の憲法は v3 の憲法そのもの」は v3 の設計を先に決めていないか。連絡は「v3 = 1 つの憲法」「設計は folio init の骨格から起こす」と書いており、本判断はその字を folio2 の決定 (3) の限定に写しただけである。ただし「1 つの憲法」が folio2 の憲法を育てたものか新しく書くものかは連絡に無い。前者なら v3 の置き場は folio2 の置き場そのもので、②の「外部の利用者」が最初から成り立たない（撤退条件 (1)）。

## 4. 起草役の総合

- 中心（ADR-16 を生かしたまま利用者を v3 の設計の置き場へ読み替える・判定点 ①〜③ を保つ・scribe2 の移行のためだけの論点を閉じる）は支持。
- 条件付きで直した所は 3 つ。v3 を外部の利用者と数える条件を「合流の前」に限った（決定 (1)・撤退条件 (1)）。判定点 ③ の記帳に読んだ器の組み立てを足した（決定 (1)）。ADR-3 決定 (7) の撤去の句も閉じた（決定 (3)・改訂の欄）。
- 新しい所見 1 つ: 骨格の命令の雛形は scribe2 の形（本来の憲法を指す）で、v3 では書き換えが要る（帰結）。控え 7 件に無い（改訂 c: 控え f2-648.196 として起票され、控えは 8 件になった）。
- 残る危うさ: 「1 repo」がどの repo かと、合流の時機。folio2 の repo を v3 に育てる形なら、本判断の「外部の利用者」は発効の直後に崩れる。撤退条件 (1) が 1 回で持ち主へ上げる。

## 5. 独立の検証役へ渡す問い（席が立てるなら）

1. 決定 (1) の narrow の読み（利用者の名の置き換えを「出口と数える状態が減る」と読んだ）は、欄の決まりの revises と supersedes の分け方に照らして成り立つか。案 b との費用の比べ方は偏っていないか。
