## 1. 設計

### (a) いま起きていること（実測・数え方は (i)・参考値は base での測り・ADR-15 決定 (5)）

`folio check` の口 `crates/folio/src/check.rs`（層 2 検査する・正規化 880 行）の `check_dir` は、正本 7 file の床を数えたあと、最後の文で凍結の書き手 `crates/folio/src/freeze.rs`（層 3 導出する）の後始末の本体 `freeze::after` を自分で呼び、判定と後始末の結果の組を返す。設計ノート §3-b の 7 番の形（同居しているのは口の側で、口の本体が下の層に居座っている）である。

1. 口が後始末へ渡すのは 6 つである。検査する dir・旗・凍結 anchor の列の検査が残した列の結果（便 111 で `phase.rs` へ降りた型）・読めた判断の記録・id の消失と改番の検査が読んだ現行の id・判定の束（後始末が違反を足すので可変で渡す）。列の結果と判断の記録と現行の id は、口の中の局所の変数で、判断の記録が読めなかったときは無い（ADR-15 決定 (3)）。
2. **これが層が上がる辺 `check` → `freeze`（層 2 → 層 3）の唯一の出どころである。** 口が `freeze` を名指すのは後始末の本体を呼ぶ 1 か所と、その取り込みの 1 行だけである。
3. 口を呼ぶのは 2 か所だけである（src と歯の全 file を名指しの字で数えた）。入口 `crates/folio/src/main.rs`（層 5）の `folio check` は 3 つの旗から旗を組んで口を呼び、後始末の結果が同じ版の断りなら断りの 1 行を出して終了コード 1 で終わり、そうでなければ違反の行・まだ分からないの行・判定の 1 行を出してから、貼れる差分の行か凍結の 1 行を出す。判定（3 値と終了コード）は後始末が足した違反を含む。配信 `crates/folio/src/site.rs`（層 5）の `folio build --write` は旗なし（`Flag::None`）で口を呼んで床の判定だけを使い、後始末の結果は捨てる。
4. 後始末の本体は旗で分かれる。旗なしの腕は dir も材料も判定の束も読まずに何もしない形（`After::Nothing`）を返す。`--emit-amends` は差分の行を組み、`--freeze-anchor` は凍結するか凍結しない 1 行を返し（凍結の検査で違反を足すことがある）、`--freeze-ids` は id の凍結を書くか凍結しない 1 行を返す。**旗なし以外の腕は判定の束を変えうるので、判定を出す前に 1 度だけ呼ぶ順が振る舞いの一部である**（(f) の 2）。

区間の外に定義がある名の列挙（ADR-15 決定 (5)・設計ノート §5-a の 5）: 入口へ移す呼び出しが使う名は、後始末の本体（層 3）と、口の引数の dir と旗（入口では局所の変数）と、口の中の 3 つの局所の変数と判定の束である。3 つの局所の変数は新しい材料の型に載せて返すので、その型の欄が名指すのは列の結果の型（層 1 の `phase.rs`）・判断の記録の型（層 2 の `adr.rs`）・現行の id の型（層 2 の `ids.rs`）で、口はどれも既に名指している（下向きか同じ層）。入口が新しく名指すのは後始末の本体の区切り `freeze`（層 5 → 層 3 の下向き）だけで、入口は区切りの宣言で既に持っている。上の層を名指す名は 1 つも無い。写しの repo に区間を当て、組み立て（`cargo build --all-targets`）を 0 警告で通して確かめた。

便 111 の後の 層が上がる辺は **1 本**（参考値）。境界の歯の file の凍結した一覧と一致している。

### (b) 直す先 — 口は後始末を呼ばず材料を返し、入口が口を出た直後に 1 度だけ呼ぶ（ADR-15 決定 (3)(5)・設計ノート §4-b の便 112 の行）

**2. 入口**（`main.rs`）。口を呼ぶ行を、判定の束を可変で受けて材料を受ける形に替え、**その直後に**後始末の本体を 1 度だけ呼ぶ（dir・旗・材料の 3 つ・判定の束を、口が渡していたのと同じ順と同じ値で渡す）。注の 1 行を添える。後始末の結果を読む行（同じ版の断り・違反と判定の印字・差分の行と凍結の 1 行）と終了コードは 1 字も動かない。入口は後始末の本体を区切り名つきで呼ぶ（区切りの宣言で持っている名なので取り込みの行は足さない）。

**3. 配信**（`site.rs`）。口の結果の組の 2 つ目を受ける束縛を、捨てる形（`_`）に替える（1 行）。**配信は後始末を呼ばない。** 配信は旗なしの定数で口を呼び、後始末の旗なしの腕は何も読まず何も書かないので、呼ぶ行を足しても振る舞いは変わらず、呼ばない行を足す理由も無い（(c) の 2 行目・(f) の 2）。

**この 4 file では、上の箇条の行のほかは 1 字も動かない。**

### (i) 数え直す手順（誰でも撃ち直せる形・規則の表の行 D-13）

本便の契約が挙げる数は全部 **参考値**で、正本は実測である。組み直す手順は設計ノート `docs/design/module-map-2026-09-23.md` の §7 と同じで、次の 6 つである。起草役の台本（区間を当てる 1 本・走査・行数・計器 3 本・変異・出力の比較 2 本・受付の再現）と実測 patch は `~/.local/share/folio2/handoff-2026-09-23/` の起草の記録 `d112-draft.md` が場所と撃ち方を持つ。

1. **正規化行と余地**: 空行を含む全行を数え、1 行の字数（Unicode の字の数）が 120 を超える行は 切り上げ(字数 ÷ 120) − 1 だけ足す。余地 = 1,500 − その値。
2. **辺と層の向き**: 設計ノートの冒頭の走査の式に字面の剥がしを足したもの（注釈と字面を剥がし、絶対の道と括り書きを解き、入口だけ接頭辞なしも数え、自分自身は数えない）を当て、層の割り当てで 下向き / 同じ層 / 上向き に分ける。境界の歯そのものがこの式を持つので、`cargo nextest run -p folio --test modules` が数え直しである。起草役の独立の走査では、base が 50 file・243 辺（下 171・同じ層 71・上 1）、本便の後が 50 file・243 辺（下 172・同じ層 71・上 0）だった（参考値）。消える辺は 1（口から凍結の書き手への上向き）、足す辺は 1（入口から凍結の書き手への下向き）。
3. **見え方と歯の名**: src 全体で、道具の中で公開の印（`pub(crate) `）を含む行と、行頭の公開の印（空白の後の `pub `）の行と、再輸出（`pub use` と `pub(crate) use`）の行を base と比べる（128 → 128・365 → 369・3 → 3）。行頭の公開の印の増分が、足した材料の型とその欄の行だけであることを diff で確かめる。歯の名は `cargo nextest list --workspace` を base と並べ、sort して比べる（違い 0）。
4. **4 つ目の受入（計器）**: base と本便の後の写しそれぞれに計器の台本を当て（後始末の本体を包み、口の頭に 1 行を足す）、計器の記録の file を環境変数で渡して workspace の nextest と (f) の 1 の 2 つの比較を撃つ。あわせて、判断の記録の dir（adr/）を消した写しと、正本 1 file（srs.yaml）を消した写しに、--emit-amends・--freeze-anchor・--freeze-ids を 1 回ずつ撃つ（材料が無い場面・workspace と (f) の 1 の場面は旗つきでこれを通らない）。記録を比べる台本は、起動ごとの並び（口と後始末の順と回数）を副命令ごとに数え、起動の番号を外した行の多重集合を副命令ごとに比べる。期待は、`folio check` の並びと多重集合が base と同じで、`folio build` の違いが旗なしの腕の回だけ（判定の束の数が呼ぶ前と後で同じ・何もしない形）であること。
5. **出力の byte**: base と本便の後の binary で、(f) の 1 の凍結の旗 16 通りと、`folio build --write`・`folio ceiling --write`・`--check`・`--refute`・`--stamp`・`--gate`・`folio intake --print`・`folio graph --print`・`folio parts --print`・`folio parts --check` を撃ち、`diff -r` と `cmp` で比べる。凍結の旗と `--refute` と `--stamp` は書くので、写しに当てる。生成区間は `folio schema --dir design-intent --check`。
6. **便の diff の大きさ**: base の commit と便の commit の差を byte で測る。
