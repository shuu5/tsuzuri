# ADR-8（草案）の敵対検証 — 独立の文脈・読み取り専用・2026-09-19

読んだもの: `design-intent/adr/ADR-8.yaml`（proposed）・憲法・rules・要件書（scope / GOAL / FR5 / NFR1 / CON5 / CON6）・`adr/schema.yaml`・v1 の実測目録・床の実装（`crates/folio/src/link.rs` `vocab.rs`）。

## 発効を止める重さ（3 件）

**B-1. 天井の 3 値を誰も消費しない — 教訓 ① と ⑤ が決定に写っていない。** 決定 (4) は「床の合格の名札と同じ欄に置かない」（P-3.3）＝分離までしか書かない。v1 の不変条件は `GREEN ⟺ (床 全通過) AND (天井 合格)` で、所見が残る限り着地は既定で止まる（v1 目録 §3・§7 の 3 と 6・`ceiling-commit-check` = refuted と明示 medium / low 以外は全 block）。ADR-8 で止まるのは「同じ場所の同じ重さの所見が R-7 の回数を超えて残った」ときだけ（決定 (5)）＝1 本目の「止める」所見は反証を生き延びても何も止めない。天井が不合格・まだ分からない のとき何が止まるのか（便の着地か・面の発行か）が決定にも帰結にも無く、basis の FR5 と P-4 は本文で 1 度も引かれていない（実測: basis 23 id のうち P-4・P-10・D-5・FR5・NFR1・GOAL4・CON5・CON6・ADR-3 の 9 個は本文に出ない）。判定 = **退ける**。直すなら: 「完成の合格は床の全通過と 4 観点すべての合格を同時に満たしたときだけ／天井が合格でない間は着地を既定で止める」を決定に 1 文足す。

**B-2. 天井が「回ったか」も「見つける力があるか」も測れない。** 決定 (4) が数えるのは 欄・3 値・観点の一覧の一致・根拠の逐語の実在 の 4 つ。逐語の照合は「正本に無い文を引く」捏造しか防がず、**合格側の 3 値には根拠の逐語が付かない**ので、AI を 1 度も回さずに「4 観点すべて合格」と書いた所見 file を床が区別できない。v1 の `ceiling-precheck`（床が真に `CEILING=PENDING` を出したかの fail-closed 確認・SKIP の偽装の排除）に当たる仕掛けが無い。加えて P-10.1 は「検査は…独立した凍結 anchor を 1 本以上持つ」で床に限定していないのに、帰結の受入基準は「材料の束が凍結 fixture から決定的に組める」＝束の組み立ての anchor までで、既知の欠陥で所見が出ることを見る赤い試験が無い。P-4.1 の穴でもある。判定 = **退ける**。直すなら: 凍結 fixture に「仕込んだ欠陥 1 つ + 出るべき所見の最小集合」を 1 本置き、合格の観点にも「読んだ欄の一覧・材料の束の要約値・起動の記録（モデル・念入りさ・時刻）」を必須欄として要求し、欠けたら「まだ分からない」に落とす。

**B-3. 撤退条件が P-8.1 の「捨てる条件」でなく、② は発効時点で数えられない。** 3 条件はいずれも「見直す判断の記録を起こす」「持ち主に問う」「形を見直す」で、**決定そのものを捨てる条件が 1 つも無い**。前例（ADR-5 / 6 / 7）はいずれも「決定 (n) を捨てて案 b へ移るかを持ち主に問う」と捨てる対象と移り先を名指す。② は「天井 1 周の予算の rules 行の値」を起点にするが、その値は発効時点で「未定」。しかもその行は `rules.yaml` の `schema.excluded`（what: 時間・費用／why: 測る仕組みが別で凍結できない・要件書 not_frozen）と衝突し、今の rules 表には置けない。判定 = **退ける**。直すなら: ① を「退けられた『止める』所見が半数を超えたら、決定 (1) の 4 観点を捨てて数と問いの文を組み直す」と捨てる対象を名指す形にし、② は台帳の実測に紐づけるか `schema.excluded` の改訂（裁定 id 付き・P-17.1）を前置する。

## 直すとよい

1. **観点 ④ に床の領分が混じる。** 「版管理の中の code・契約表・台帳の着地の記録との食い違い」は、参照 id の未解決（R-4）・着地の印（FR13 = 印が無ければ「まだ分からない」）・id の索引（FR14）として床に在る／建つ項目を含む。根拠 = P-3.1。判定 = **退ける**。直すなら ④ に「床が数える一致は除き、意味の食い違いだけを見る」を 1 文。
2. **観点 ① の母集団を既存の委譲先で固定せよ。** 面は正本の逐語で組み AI の散文 slot が無い（P-6.1 / P-6.2）ので v1 型の ① は空になるが、平易文（plain）は人が書く自由文で、R-9 の note・R-10 の note・`adr/schema.yaml` の limits_note・同 figures_note（refs の行き先は床では数えない）が既に天井へ投げている。判定 = **支持（① は空でない）**。直すなら ① にこの 4 つを id で名指す。
3. **案 c の却下理由に事実でない主張が 2 つ。** (a)「P-16.2 と噛み合わない」— P-16.2 は「最上位を*求めない*」の must-not で、folio が opus で回すことを禁じない（D-1 は道具の内側 opus までを許す）。判定 = **退ける**。(b)「P-1.2 に近づく」— 採用案 a でも folio は所見から 3 値を出す（決定 (4)）ので距離は変わらない。判定 = **退ける**。残る「鍵と課金（A-1）」「席と器が既に起動の口を持つ」は事実で却下を支えるが、A-1 は binds: both なので義務は消えず席へ移るだけ。直すなら理由をこの 2 点に絞り、A-1 の側を「folio が鍵と課金を持たない」に限定する。案 e の「反証の 2 段目が組めない」も言い過ぎ（重さの欄があれば 1 本でも組める）ので「所見の場所と重さが粗くなる」に弱める。
4. **反証の倒し方が無い。** 決定 (3) は反証の結果が「まだ分からない」のとき所見が残るか消えるかを書いていない。v1 の `finding-refuter` は中立で、判断不能は uncertain として fail-closed に残す。直すなら「反証が『まだ分からない』なら所見は残す」を 1 文。
5. **決定 (1) が 2 つの物を同一視している。** 「密度 profile のデータ（新しい正本 = 天井の正本）」の密度 profile は R-5 の閉じた一覧に載る型で、追加は P-2.4 の判断の記録を要する。別 file なら P-5.3 の語を「設定のデータ」と一般に読む旨を書き、R-5 の一覧に触れないと明記せよ。
6. **順序（決定 (6)・帰結 1）は許される。** amends は空で、条文と schema 節・前文が変わらないので A-2.2 のとおり改訂でない（N-5 の mechanism 欄は limits_note のとおり A-2.2 の外）。要件書 v1.6 の同梱は P-13.3、rules 行の新設は P-17.1 を帰結が満たす。判定 = **支持**。直すなら ADR-7 に倣い帰結に新しい番号（FR17 以降・AC15 以降）を書く。

## 支持（穴が見つからなかった点）

- **N-5.1 に当たらない。** 逐語は「文書の型ごとの AI 係や検査の観点を増設するなら拒む」、mechanism は「閉じた一覧で持ち、一覧外・文書型専用のものは 0」。4 観点は型に依らず閉じた一覧（天井の正本）に入り、床が一致を数える（決定 (4)）。folio は係の説明文を持たないので R-1 / NFR1 に足す字は 0。
- **教訓 ③ ④ は写せている。** ③ は決定 (2) の「正本の写し（基準）」が v1 の `ceiling-anchors` に当たる。P-10.2 の逐語は「生成物どうしの突き合わせ」なので、正本を基準にする形は条文に反しない（著者 = 審査者の二重は P-10.1 の話＝B-2 へ回した）。
- **形式の穴は無い。** required 10 欄すべて在り non_empty 4 欄は非空、options は 5 案で adopted 1、retreat は kind ∈ enum と condition 非空、proposed なので承認欄と grill 欄は無くてよい。kind = measure は 3 条件とも数えた値が起点なので妥当。本文の英字語の床（`link.rs` の body_words）は実装（`vocab.rs` の words / glosses / is_id_shape）を写して回して **違反 0**（「grill 欄」「review.json」は同じ欄に「（grill）」「file（review.json）」が在るので免除）。写しでの確認であって本物の床ではない。
- **案 b・d の却下は事実に基づく。** b は v1 実測（agent 36 本・説明文 29,027 字・R-1 の由来）と一致し、d は P-3.2 / P-3.3 と持ち主の直命に反する。藁人形ではない。
