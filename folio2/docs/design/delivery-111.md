## 1. 設計

### (a) いま起きていること（実測・数え方は (i)・参考値は base での測り）

凍結の書き手 `crates/folio/src/freeze.rs`（層 3 導出する・正規化 357 行）が、層の違う 2 つの責務を同居させている。

1. `freeze.rs` は、`folio check --emit-amends` と `--freeze-anchor` の本体（後始末の本体 `after`・差分の行 `emit_lines`・凍結 `freeze`・`--freeze-anchor` 専用の言い換え `not_frozen`・版の並べ方 `ver_key` ほか）のほかに、**凍結の実行の様態の型 3 つ**（`folio check` の旗 `Flag`・凍結 anchor の列の検査が残した列の結果 `State`・旗の後始末 `After`）と、**凍結しないときの 1 行** `not_frozen_by`（違反とまだ分からないの数と旗の綴りから断りの 1 行を組む）を持つ（base の 17〜62 行の 46 行と 152〜159 行の 8 行）。
2. 凍結 anchor の列の検査 `anchor.rs`（層 2 検査する）は、旗が `--freeze-anchor` のとき現行との一致の検査を替え、列の結果を返すため、`Flag` と `State` を `freeze` の名で名指す。**これが層が上がる辺 `anchor` → `freeze`** である。
3. id の消失と改番の検査 `ids.rs`（層 2）は、旗を受け、`--freeze-ids` の後始末を返し、凍結しないときの 1 行を組むため、`Flag`・`After`・`not_frozen_by` を `freeze` の名で名指す（**`ids` → `freeze`**）。
4. `folio check` の口 `check.rs`（層 2）は、`Flag`・`After` のほかに後始末の本体 `freeze::after` を呼ぶ（**`check` → `freeze`**）。後始末の本体は凍結の書き手の本体なので本便では動かさず、この辺は残る（便 112 が口の署名を変えて消す）。
5. 入口 `main.rs` と配信 `site.rs`（どちらも層 5）も `Flag`（入口は `After` も）を `freeze` の名で名指す（下向きの辺で決まりには反していない）。

区間の外に定義がある名の列挙（ADR-15 決定 (5)・設計ノート §5-a の 5）: 型 3 つが使う名は、正本の構文の木の値 `yaml::Value`（層 1）と標準の道 `PathBuf` だけである。凍結しないときの 1 行が使う名は判定の `Report`（層 0 の `verdict.rs`）だけである。どれも区間に接頭辞なしで入るのは型の欄と引数の型だけで、上の層を名指さない。区間を切り出して、組み立て（`cargo build --all-targets`）を 0 警告で通して確かめた。

便 110 の後の 層が上がる辺は **3 本**（参考値）。境界の歯の file の凍結した一覧と一致している。

### (b) 直す先 — 型 3 つと 1 行を新しい `phase.rs`（層 1 読む）へ、字を変えずに移す

本便の契約が挙げる数は全部 **参考値**で、正本は実測である。組み直す手順は、設計ノート `docs/design/module-map-2026-09-23.md` の §7（写しに区間を当てて組み立て、走査し直す）を本便の区間に当てたうえで、次の 6 つを数える。起草役の台本（区間を当てる 1 本・走査・行数・変異・出力の比較 2 本）と実測 patch は `~/.local/share/folio2/handoff-2026-09-23/` の起草の記録 `d111-draft.md` が場所と撃ち方を持つ。

1. **正規化行と余地**: 空行を含む全行を数え、1 行の字数（Unicode の字の数）が 120 を超える行は 切り上げ(字数 ÷ 120) − 1 だけ足す。余地 = 1,500 − その値。
2. **辺と層の向き**: 設計ノートの冒頭の走査の式に字面の剥がしを足したもの（注釈と字面を剥がし、絶対の道と括り書きを解き、入口だけ接頭辞なしも数え、自分自身は数えない）を当て、層の割り当てで 下向き / 同じ層 / 上向き に分ける。境界の歯そのものがこの式を持つので、`cargo nextest run -p folio --test modules` が数え直しである。起草役の独立の走査では、base が 49 file・239 辺（下 166・同じ層 70・上 3）、本便の後が 50 file・243 辺（下 171・同じ層 71・上 1）だった（参考値）。消える辺は 4（列の検査と id の凍結から凍結の書き手への上向き 2、入口と配信から凍結の書き手への下向き 2〔入口は区切りの宣言だけになり、接頭辞つきの名指しが消える〕）、足す辺は 8（列の検査・口・凍結の書き手・id の凍結・入口・配信から新しい file の下向き 6、新しい file から判定の型への下向き 1、新しい file から `yaml` への同じ層 1）。
3. **区間の純度と見え方と歯の名**: base と本便の後の diff の足した行と消した行を多重集合で照らす（一致は 56 行＝型 3 つの 46 行と凍結しないときの 1 行の 8 行と、新しい file の空行 2 行が `freeze.rs` から消える空行 2 行と対になったもの）。移動でない行は、足した側が (g) の 25 行、消した側が旧い取り込みと区切り名の 10 行（`anchor.rs` 1・`check.rs` 1・`freeze.rs` 1・`ids.rs` 5・`main.rs` 1・`site.rs` 1）と境界の歯の file の一覧の 5 行である。見え方は src 全体で、道具の中で公開の印（`pub(crate) `）を含む行と、行頭の公開の印（空白の後の `pub `）の行と、再輸出（`pub use` と `pub(crate) use`）の行を base と比べる（128 → 128・365 → 365・3 → 3）。歯の名は `cargo nextest list --workspace` を base と並べ、sort して比べる（違い 0）。
4. **出力の byte**: base と本便の後の binary で、(f) の 1 の凍結の旗 16 通りと、`folio build --write`・`folio ceiling --write`・`--check`・`--refute`・`--stamp`・`--gate`・`folio intake --print`・`folio graph --print`・`folio parts --print`・`folio parts --check` を撃ち、`diff -r` と `cmp` で比べる。凍結の旗と `--refute` と `--stamp` は書くので、写しに当てる。
