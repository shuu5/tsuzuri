## 1. 目的と中身

① 判断の記録の面の章 05 は、正本の note の欄を見出しと段落でそのまま開いて出す。要件書の面と設計ノートの面は注を折りたたみに入れるので、面ごとに扱いが違い、長い注が章の末尾を占める。② 図の本体（SVG）には、図の道具（archify）が型ごとに持つ固定の英文が残る。箱にホバーしたときの吹き出し（title 要素）と、読み上げの名札（aria-label 属性）の末尾に 型の種別の英語が入り、頭に Focus が付く。図全体の説明（desc 要素）も英文のままである。箱と線の名札そのもの（正本の型付き記述から来る字）と凡例の中身は既に日本語で、凡例の見出しは便 67 が置き換え済みである。本便はこの 2 つを面と図の側だけで直す。正本 design-intent の下の file と図の道具 vendor/archify/ は 1 byte も触らない。

### (a) 判断の記録の面の注の折りたたみ

face_adr.rs の amends_chapter の 733〜737 行を、h3 の見出し 1 行と p の段落 1 行から、折りたたみ 1 行に替える。字面は face_index.rs 1168〜1174 行の details と同じ形で、summary の字は 「注」、中の p が note の字（escape 済み）。note が無いときは今までどおり何も置かない。章 05 のほかの節（条文の改訂・この判断で変わること・反対側からの確認・置き換えた判断・後継の判断）は触らない。

### (b) 図の英語の置き換え

figure.rs に、道具の型ごとの英文の表 1 本と、日本語を作る関数 1 本を足し、ja を型を受け取る形にする。

1. 定数 EN_BY_TYPE: &[(&str, &str, &str)] = 道具の型・説明の英文・読み上げの種別の英文 の 3 つ組を 5 行。行の順と型の字面は FIGURE_TYPES の値（architecture・workflow・sequence・dataflow・lifecycle）と同じ順で同じ字。
2. 関数 ja_name(kind) -> &str = FIGURE_TYPE_LABELS の名札から、最初の 「（」 より前だけを取る（構成図・手順図・順序図・流れ図・状態図）。名札に 「（」 が無ければ名札の全部。名札が表に無ければ Err（P-4.1）。手書きの日本語の写しは持たない（P-6.3・便 52 と同じ運び）。
3. ja(body, kind) の置き換えは今の 2 つに次の 3 つを足す。順は下のとおりで、どれも字の置き換えだけ（図の意味の属性〔箱の id・種別・名札・線〕は変えない・ADR-4 決定 (3) の範囲の内）。
   - 説明: その型の説明の英文 →「図の道具（Archify）が描いた{ja_name}。」
   - 読み上げの種別: その型の種別の英文 →「{ja_name}の要素」
   - 読み上げの頭: 属性 aria-label の名と等号と二重引用符に続く 「Focus 」（Focus と半角空白 1 つ）→ 同じ前置きに続く 「注目 」。二重引用符に続く形でだけ置き換え、ほかの所の Focus は触らない。
4. 型が EN_BY_TYPE に無ければ Err（図は描かない・面は まだ分からない に落ちる・P-4.1）。render（191 行）は tool_type で型を解いた後に ja へその型を渡す。
5. check_anchor は今までどおり deliver を直に呼ぶ（置き換えの前の出力で写しと比べる）。凍結 anchor tests/fixtures/figure/anchor/body.svg は 1 byte も変えない。
